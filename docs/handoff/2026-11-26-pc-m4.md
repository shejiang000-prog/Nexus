# PC-M4 · Windows「我的服务器」后端

基线 `8b71aad`，本地开发分支 `v2/m0-transport`。接口在 Tauri 的 `control-core` 权限组中，部署和管理由同目录的普通权限 `nexus-core.exe` 执行。桌面界面由 Claude 接入。

## Tauri 接口

| 命令 | 参数 | 返回值 |
| --- | --- | --- |
| `owner_start` | 下表的一组字段，`op` 放在顶层 | 数值型 `operationId`。参数无效或已有操作时直接拒绝。 |
| `owner_status` | `{operationId}` | `{phase, error}`。正常时 `error` 为 `null`。仅供轮询。 |
| `owner_result` | `{operationId}` | 成功后领取一次业务结果；操作失败则返回同一固定错误码。 |
| `owner_cancel` | `{operationId}` | `null`。针对指定操作请求取消。已经结束时可重复调用。 |

每个窗口进程同时接受一项管理操作，与代理连接各用一个核心进程。拿到 ID 后轮询 `owner_status`，`done` 时调用 `owner_result`。先领取结果，再启动下一项；启动新操作会替换已结束的记录。

| `op` | 其他参数 | 业务结果及含义 |
| --- | --- | --- |
| `list` | 无 | `[{serverId,label}]`。只列已绑定的服务器，`label` 是掩码 IP 和 SSH 端口；空列表为 `[]`。 |
| `discover` | `address` | `{pin}`。只探测 SSH 主机公钥，不发送密码。界面显示 `SHA256:…` 指纹，供用户与服务商控制台核对。 |
| `deploy` | `address, pin, password` | `{serverId}`。用户确认上一步指纹后调用。安装 IP 模式的 V2 和 Reality、绑定管理权，并把这台电脑登记为首台设备。 |
| `bind` | `address, pin, password` | `{serverId}`。授权本机管理密钥并读取已有账本，不重装或自动领取设备。 |
| `invite` | `serverId, days` | `{text}`，内容为「复制这条消息后打开 Nexus」、换行、完整邀请。直接交给系统分享或显式复制。 |
| `devices` | `serverId` | `[{deviceId,accountId,name,expiresAt,expiryKnown,revoked}]`。到期时间为 Unix 秒；`expiryKnown=true` 且 `expiresAt=null` 表示永久，`false` 表示旧节点未提供到期信息。 |
| `renew` | `serverId, accountId, days` | `null`。使用设备行的账号 ID。有限续期从服务器当前 UTC 时间和原到期时间两者中较晚者起算。 |
| `revoke` | `serverId, deviceId` | `null`。使用设备行的设备 ID。界面确认撤销后调用，成功后重新取 `devices`。 |

`address` 接受 IPv4、IPv4:端口、IPv6、[IPv6]:端口，默认 SSH 端口 22。三个 ID 都是 32 位小写十六进制串。邀请与续期的 `days` 须显式传 `1..3650` 的整数或 `null`（永久）。与 Android 相同，邀请设置的是账号使用期限；一次性链接的领取窗口最长 7 天，短于 7 天的账号按实际天数计算。

## 进度、取消和错误

| `phase` | 界面含义 |
| --- | --- |
| `queued`、`connecting` | 已排队、正在连接服务器 |
| `binding`、`installing`、`enrolling` | 正在授权或核对管理权、正在安装、正在登记本机。部署在安装前授权公钥，安装后再次核对账本，因此可能两次经过 `binding`。 |
| `done`、`failed` | 已完成，可取结果；或操作失败，读取 `error` |
| `cancelling`、`cancelled` | 正在取消；或操作已取消 |

| 固定错误码 | 界面提示要点 |
| --- | --- |
| `invalid_request`、`invalid_endpoint` | 参数或天数有误；服务器 IP 或 SSH 端口格式有误。 |
| `host_key_changed` | 指纹与用户确认或已保存的记录不符，停止登录，请向服务商核实。 |
| `ssh_timeout`、`ssh_refused`、`ssh_auth`、`ssh_failed` | 连接或命令超时；SSH 拒绝连接，核对端口；密码或管理密钥未获授权；其他 SSH 操作失败。 |
| `already_installed`、`not_installed` | 已部署，请选择绑定；尚未部署，请选择部署。 |
| `unsupported_arch`、`node_download`、`node_checksum` | 服务器架构不支持；服务器无法下载同版本节点；文件摘要不符，安装已停止。 |
| `install_port_occupied`、`install_failed` | 安装器预检发现端口占用；其他安装错误。 |
| `server_not_found`、`ledger_failed` | 本机没有该绑定；远端账本命令失败或返回数据无效。 |
| `owner_storage`、`owner_busy` | 本机管理记录无法读写或解密；已有管理操作，稍后重试。 |
| `enrollment_failed`、`invite_rejected`、`node_unreachable`、`identity_busy`、`key_missing` | 首设备登记失败；节点未接受邀请；节点连接失败；设备身份正在使用；设备密钥丢失。 |
| `owner_operation_changed`、`owner_pending`、`owner_result_taken` | 操作 ID 已过期或不存在；尚未结束；成功结果已领取。 |
| `cancelled`、`update_busy`、`missing`、`generic`、`owner_failed` | 已取消；客户端正在更新；缺少核心；核心无法启动；管理操作未完成。 |

取消和正常退出都会关闭专用 stdin。核心取消 SSH 上下文，向运行中的 SSH 命令请求终止并关闭连接；壳给子进程最多两秒自行退出。已经写入远端的公钥、安装结果或账本更改会保留。若部署中断，核对服务器实际状态，然后以同一地址和指纹重试部署；已完成的安装可接续首设备领取。普通绑定只接管管理权。

## 凭据、版本与验收

- root 密码只用于本次操作，通过匿名 stdin 传给核心。状态只传固定阶段和错误码，邀请只出现在专用业务结果中。服务器列表仅显示掩码地址，远端 stdout/stderr 不进入应用日志。
- Windows 按当前用户用 DPAPI 加密 `%LOCALAPPDATA%\Nexus\desktop\owners.dpapi`，保存主机指纹、地址、Ed25519 管理密钥及进行中的首设备登记。远端仅追加带 `restrict` 的管理公钥。后续管理使用密钥。首次部署会暂存首账号收据及待领邀请，支持断链后用同一账号、邀请和设备请求接续；成功后清理临时记录。设备私钥沿用原有 CNG 流程。
- 安装复用 Android 的 `download_node.sh`。服务器从对应桌面版本的 GitHub Release 下载 amd64 或 arm64 节点，核对内置 SHA-256 后才执行安装器。CI 从同标签的 Android 构建取得两份已与 APK 核对的摘要；本地 2.0.1 离线构建使用已发布 APK 的同一对摘要。SSH 库沿用锁定的 `golang.org/x/crypto v0.58.0`，无新增或升级模块。
- 快速验证入口为 `tools/build_desktop_core.py --test-owner`（其余参数沿用桌面核心构建）。进程内 SSH 服务仅监听回环，覆盖密码成功和失败、指纹变化且未发送密码、拒连、超时、自定义端口、端口占用、摘要错误阻止安装，以及绑定、邀请、设备列表、续期和撤销的完整命令往返。回环 TLS/H2 服务故意丢弃首次领取回包，重试后确认只创建一个账号、只签发一份邀请、两次使用同一个设备请求 ID，并激活本机 CNG 身份。三项 Go 检查通过（0.692 秒）。
- Tauri mock runtime 使用实际命令权限和真实核心，核对空列表、单次结果领取、错误 ID 隔离、并发拒绝，以及 SSH 握手期间取消。两端 release 构建离线通过。未调用真实安装器、连接真实服务器、改动 NexusLab V1、本机系统代理或 TUN；真实 VPS 部署由 Claude 用正式版验收。

人工核对了指纹先于密码认证、固定远端命令与参数、DPAPI 记录、结果和状态的分离，以及发布摘要来源。Codex Security 差异扫描未能解析本机工作树的 HEAD，未生成插件报告。

## Claude 评审

结论：通过，可以接界面。

- 复现：`build_desktop_core.py --test-owner` 三项 Go 测试通过（0.79 秒）；`cargo test` 通过。
- 节点摘要：离线构建内置的 amd64/arm64 摘要与本地留存的 v2.0.1 正式版 `SHA256SUMS.txt` 一致；`download_node.sh` 与 v2.0.1 相同。CI 改为从同标签 Android 构建取摘要，Windows 作业新增 `needs: build`，发布开关仍默认关闭。
- 与 Android 对齐：授权公钥命令（`restrict`、`grep -qxF`）、安装参数（`--public-host`、`--protocols`）、邀请领取窗口最长 7 天、续期起算方式一致。
- 安全：`discover` 在主机密钥回调里中止，确认不发送密码；部署/绑定用固定指纹校验；远端命令只拼接 netip 规范化后的地址、正则校验过的临时路径和 32 位十六进制 ID，没有注入面；状态管道只有固定阶段和错误码，壳层对结果按操作做白名单校验；DPAPI 记录里不含密码（测试已覆盖）。
- 小问题，不阻塞：
  1. 取消发生在下载或安装阶段时，`/tmp/nexus-upload.*` 的清理命令因上下文已取消而不会执行，服务器上可能残留一个临时文件。
  2. Go 字符串里的密码无法主动清零，只能等回收；stdin 原始行已清零，可以接受。
- 界面取舍（Claude 处理）：手机版是首次连接时直接记住主机指纹。电脑版界面也按这个思路，`discover` 后直接进入部署，指纹只在进度里小字显示，不增加确认步骤。
