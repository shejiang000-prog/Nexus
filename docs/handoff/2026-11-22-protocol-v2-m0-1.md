# 协议 V2 · M0 第一部分：传输层

开发分支从 main `1b2fa5e` 建立，规范分支基线为 `643e3d7`。本轮本地签入 Go 传输模块、Caddy 节点入口、补丁工具和 Android 合编回归入口。正式 API 见开发分支的 `docs/protocol/v2-transport-api.md`，站点对照详表见规范分支 `docs/protocol/v2-design.md` 的「M0 实测」。

## 改动

- `v2/proof`、`transport`、`udp` 实现 TLS exporter 连接绑定、一次签名、乐观 TCP 和两种 UDP 承载。选择器按第 6 轮保留首个静默窗口预建 H2、第二个窗口比较以及旧流收包判定。H2 将出站 HPACK 表限制为 1 字节，容不下任何证明项；本版 QPACK 编码器使用静态表和字面量。
- `v2/server` 和 `cmd/nexus-node` 处理已认证 CONNECT，将其他请求交给后续 Caddy handler。受信配置可按入口设置静态内存设备公钥；目的域名只解析一次，任一答案命中禁止段则拒绝，实际拨号使用通过检查的字面地址。实验室仅对回显服务的特定地址与端口临时放行。
- `tools/prepare_v2.py` 从 go.sum 校验上游模块、应用五份补丁并生成仓库外的 modfile。`tools/build_v2_aar.py` 将客户端与固定 libXray 绑定到同一个 Go 运行时。GitHub Actions 新增独立 Go job，沿用原有 Android job。许可证列入开发分支 `THIRD_PARTY_LICENSES.md`。
- `v2/internal/xconnect`、systemd 服务定义、Android Application、可选 Gradle 合编和 M0Check 完成 H2 初始化。上游 Go 1.27.4 的 `src/net/http/internal/http2/http2.go:50,59–60` 在 init 中读取环境并保存布尔值；`server.go:776–777,2128` 读取已保存的值。x/net v0.60.0 的 `http2/http2.go:62–63` 在包初始化时做同类处理，`transport.go:2568` 接收对端 SETTINGS。Go 节点在 main 发现环境不符合要求时保留其他项并重新执行一次，Android 在加载合编库之前调用 Os.setenv。[Go 源码](https://go.googlesource.com/go/+/refs/tags/go1.27.4/src/net/http/internal/http2/http2.go) · [x/net 源码](https://go.googlesource.com/net/+/refs/tags/v0.60.0/http2/http2.go)

## 留给下一轮

1. 对标准及 legacy Go 升级执行同一套握手、门槛回归。此轮验证了原型选择器移植和连接回显，没有重跑 100 次故障注入或重新比较 Chrome 握手分布。Android 本轮仅验 x86_64 合编、H2 UDP 和指定的三项 Xray 回归；arm64、真机 VPN、系统物理网络绑定和 release 尚待验收。
2. 固定互通向量已验证设备证明、邀请字节、跨连接失败、同连接并行和撤销后无法另开流。向量包含 0-RTT 和兑换事务的预期状态；真实 0-RTT 报文、邀请并行扣次及到期、存储故障和活动流撤销时限须专门验收。设备账本和邀请兑换服务归 M1。
3. 初始业务限制为每流 16 KiB。服务端完成验证及拨号才消费请求体；HTTP 栈预读的全连接 64 KiB / 2 秒上限尚无负载证据。签名回调在模拟器通过，StrongBox 尚未测量。systemd 单元未经系统安装；云端 Actions 未触发。
4. DATAGRAM 配置只解决一个监听上的 H3 能力宣告。进程级 H2 SETTINGS、QUIC 流控窗口仍可观察。三组顺序重启，未测同进程多监听热重载或大样本时序判别。
