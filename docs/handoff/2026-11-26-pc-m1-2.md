# PC-M1-2 · Windows 订阅导入

基线 `ab4d62a`，本地开发分支 `v2/m0-transport`。配套的 `nexus-desktop.exe` 和 `nexus-core.exe` 位于 `E:\代理软件\验收包\PC-M1-2`。

## 使用

在「我的订阅」粘贴 HTTPS 订阅地址或节点分享链接，点「添加」。选中节点后点「使用此节点」，回首页点「连接」。首页的「连接来源」可切回原 V2 邀请身份。与 v2rayN 并用时，先关闭「系统代理」，再把实际 SOCKS5 或 HTTP 回环端口填入目标应用。

链接来源支持手动刷新和删除。直接添加的分享链接保存在本机，可删除。订阅提供流量或到期信息时，页面展示 `Subscription-Userinfo` 的可用字段，也识别 Android 使用的“剩余流量”和“套餐到期”信息行。刷新失败继续使用上一次成功保存的节点。刷新后，只有节点名称、协议和出站参数均匹配才沿用原选择。

## 实现与边界

- `apps/shared/subscriptions` 从明文分享链接、Base64 链接组和 Clash 节点列表生成受限的单一出站。使用构建中锁定的 libXray share 转换器和 YAML 解析器。内容上限 512 KiB，结构深度上限 24，每个来源最多 2048 个节点。重复键、别名、关闭证书校验和远端提供的入站、路由、控制接口均被拒绝。
- Windows 使用同一个核心加载 VLESS、VMess、Trojan、Shadowsocks 和 Hysteria2 出站。SOCKS5/HTTP 入口、系统代理所有权和恢复规则、端口避让、分流与 DNS 策略沿用 M1。Android 生产代码继续使用 Kotlin；Android 由 Shoes 承载的 TUIC、AnyTLS 超出本次固定 Xray 的协议范围。
- 每个来源单独用当前用户 DPAPI 加密，位置为 `%LOCALAPPDATA%\Nexus\desktop\subscriptions\<来源ID>.dpapi`。加密后才写临时文件和替换正式文件。下载和解析在锁外进行，写入前在锁内核对版本，防止刷新覆盖较新数据或复活已删除的来源。壳通过匿名管道传链接，WebView 仅读回显示名、协议、流量、到期和不透明 ID。核心状态和错误使用固定码。[Microsoft DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata)
- HTTPS 下载使用正常证书验证，最多跟随三次重定向，禁止 HTTPS 降级。仅本机回环 IP 允许 HTTP。启动订阅节点时只探测所选节点本身。RAW/TLS、Reality、Hysteria2 检查相应传输握手，延迟建链的 HTTP 类传输检查 TCP 可达性。端到端转发与代理凭据由实际业务流量验证。

## 快速验收

| 项目 | 结果 |
| --- | --- |
| Android / Go 对照 | 对同一批 10 组合成输入，Android 宿主 JVM 与 Go 均接受 4 组、拒绝 6 组。9 个有效节点的显示名、协议和完整出站 JSON 一致。另查了超长正文、过深结构、远端控制和 TLS 文件字段。 |
| 导入和存储 | 本机 HTTP 合成订阅完成添加、DPAPI 解密重读、刷新、失败后继续使用旧节点和删除。磁盘文件与公开 DTO 均未出现合成链接令牌、节点地址或密码。另用最终核心导入合成 WebSocket 分享链接，stdout 只有一行公开 JSON，stderr 为空。 |
| Windows 界面 | 真实 Tauri 窗口完成添加、刷新、选择、连接、断开和删除。页面显示两个实验节点、剩余 10 GiB 和到期日 2026-12-31。检查了 1080×720 主窗口和 440×680 暗色窄窗。 |
| 实际连接 | NexusLab 的 VLESS Reality/Vision 用全局模式，Hysteria2 用分流模式并验证证书指纹。两个节点分别经指定 SOCKS5 和 HTTP 入口收到带随机标识的实验回显，共 4 次。不可达的合成节点返回 `node_unreachable`。 |

在已有 M1 工具链与规则缓存的 Windows x64 主机上，从仓库根目录重跑：

```powershell
python tools/build_desktop_core.py --test-subscriptions --test-routing --rules-cache E:\temp\nexus-split-data\fresh-inputs E:\temp\nexus-round5\libXray apps\desktop\target\debug\nexus-core.exe
cargo build --locked --offline --manifest-path apps\desktop\Cargo.toml
```

宿主对照使用 Robolectric Android 15、基线 Kotlin 解析代码及调用固定版 libXray 的宿主转换桥。仓库中的 `apps/shared/subscriptions/testdata/parity.json` 保留合成输入与 Android 的预期出站，日常 Go 快测无需 Android 环境。在本次验收机上，将该文件复制到 `E:\temp\nexus-pcm12-jvm\samples.json`，在此目录使用 Gradle 8.14.3 执行 `--offline testDebugUnitTest` 可重新生成 `results.json`。

应用验收仅使用合成数据及 NexusLab。真实系统代理、TUN、防火墙、系统网络配置均未修改。没有新增项目依赖或改动节点端。窗口验收中，Windows 的 `py` 启动器因隔离的 `LOCALAPPDATA` 自动下载了 Python 3.15.2，已从隔离目录卸载并核对原用户环境。

人工审阅覆盖了远端字段白名单、证书策略、刷新时的所有权、明文日志和 Tauri 公开字段。Codex Security 的差异扫描启动时未识别本地 Git 工作树的 HEAD，未生成插件报告。

## Claude 评审

结论：**通过**，没有必须修复的问题。

复现：`build_desktop_core.py --test-subscriptions --test-routing` 通过，包括共享解析、与 Android 的对照样例以及分流测试；`nexus-core.exe` 32,613,888 B；`cargo test` 和 `cargo build` 通过。测试数据只用了文档保留地址和公共域名，没有私有信息。联网和窗口验收采信本交接。

代码检查：
- 出站字段采用白名单：协议、传输和 TLS 字段逐层限定，不接受任意 Xray JSON，也拒绝关闭证书校验。保存过的节点在构建前会再校验一次。
- 下载：HTTPS 使用正常证书校验，重定向最多三次、禁止降级，并去掉 Referer，避免订阅令牌外泄；明文 HTTP 只允许回环地址。User-Agent 与 Android 相同。
- 存储：每个来源单独用 DPAPI 加密。刷新先在锁外下载，写入前在锁内核对版本，被删除的来源不会因刷新而恢复。
- 连接：只预探所选节点本身，之后沿用 M1 的系统代理、分流和端口策略。

后续可改进（不阻塞）：
1. 核心从 21 MB 增至 31 MB，因为加入了 Xray 的 JSON 配置构建和多种协议。发布前可以评估是否值得精简。
2. Windows 暂不支持 TUIC 和 AnyTLS（Android 用 Shoes 支持）。订阅里的这类节点在 PC 上会被跳过，界面应提示「此类节点暂不支持」，而不是让用户以为订阅不完整。
3. 订阅总是直连下载。如果机场的订阅域名在国内被墙，可以加一项「直连失败时经当前连接重试」。
4. PC 版发布前仍需做真实系统代理验收（用户已同意稍后进行）。
