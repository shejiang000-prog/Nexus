# M3 第 1 部分 · Android 接入 V2 私人节点

2026-11-23。开发基线 `c8db071`，传输接口基线 `607a3f8`。网络验收使用正式合编的原生库和隔离的 Debug 应用 ID。随后提交 `7eb2fe4` 只调整短竖屏布局和对应的界面断言。Release 使用相同原生库。

## 本轮交付

- Gradle 的 Debug、Release 默认从锁定的 libXray 与 V2 源码构建同一个 AAR。arm64-v8a 和 x86_64 各有一份 Go 运行时，两份 `libgojni.so` 都核对架构、Go build info 与 go.sum。相同工具链、源码和绝对工作目录离线构建两次得到相同字节。AAR 为 26,367,642 B，SHA-256 为 `e7f7f23b2ba283e367d0b7c76a4b578984f0d9dfea5ff1b5a60fc6cb673e1c3d`。
- 邀请可由粘贴与扫码进入。界面显示域名和端口，用户确认后才以 Android Keystore P-256 密钥兑换。优先使用可用的 StrongBox。为重试只保存请求 ID 和密钥别名。应用禁用备份，成功回执保存设备 ID 与账户到期信息。旧节点未提供到期字段时显示「到期时间未知」。含 SPKI pin 的邀请在本机拒绝。详情页显示设备 ID 简写，本机移除会删除密钥和关联设置。
- 用户批准两处加法扩展。独立兑换绑定在同一条 TLS 连接上签署 exporter 证明，节点成功回执增加可空的账户到期时间。TCP 增加 `Stream.CloseWrite`，H2 和 H3 都测试了目标读到 EOF 后回复 147,456 字节。已有 Start、TCP、UDP 方法及签名保持兼容。
- VPN 复用 Xray 的 Android TUN、路由、DNS 及按应用名单，只有选中 V2 的代理出口交给该设备的 V2 会话。TCP 两端可独立半关闭，UDP 按目的地址建立关联。认证失败、撤销或到期会清除自动恢复请求，界面提示用户联系管理员。错误 1–7 均有中文提示，暂时的网络或资源错误按退避重试。第三方订阅继续走原有引擎。
- Android 优先发起 H3，250 ms 后并行 H2。业务等待且 QUIC 连续两个 500 ms 窗口没有收到数据时，用同源 32 KiB 健康对象确认阻断与 H2 可用性。恢复时在 H2 至少驻留 30 s，以同一 H3 候选连续两次成功读取为准。新流改走 H3，原 H2 流可完成。已经阻断、无进展的 H3 流可关闭，客户端不会重放可能已交付的数据。安装器生成供两种承载读取的健康对象。旧节点需补齐同源 `/health.bin` 路由并重载。

### 必须修复

1. **空闲耗电。** 两处周期流量会让射频几乎无法休眠，熄屏时也一样。按交接所述，主流 VPN 客户端空闲时没有这类轮询。
   - `V2Session` 每 10 s 发起一次 CONNECT-UDP 认证探测。
   - 选择器停在 H2 时，Android 分支每 30 s 无条件回探 H3，不检查业务，失败也不退避。每次回探都新建 QUIC 连接，并调用一次 Keystore 签名。
   - 蜂窝网络的 RRC 空闲释放约 10 s，所以射频基本一直处于连接态。
2. **到期时间在本地强制执行。** `expiresAt` 只在兑换时写入，之后从不刷新，但 `V2Session` 会据此本地判定错误码 3，并清除自动恢复。由此产生两个问题：
   - 管理员续期后，客户端仍然拒绝连接，而且重新导入同一邀请会返回旧记录，只能删掉后重新领取。
   - 手机时钟不准也会误判。
3. **健康对象成为节点指纹。** 安装器为所有节点在 `/health.bin` 返回同样的 32,768 个 `0`。未认证的扫描者发一个 GET 就能识别 Nexus 节点，这违背了"握手伪装持平最强竞品"的门槛。
4. **Android 识别不了 UDP 限速。** 在 `androidVPN` 分支里，只要收到任何字节就算有进展；只有 H3 完全失败时才切到 H2，"慢于 H2 四倍"的规则被删掉了。国内常见的情况是运营商对 UDP 限速或高丢包，而不是完全阻断。这时客户端会一直留在很慢的 H3 上，削弱了"自动 UDP→TCP 回退"这一卖点。

### 应修复

5. **目标先半关闭的方向不支持。** 评审用例 `TestZZTargetFirstHalfClose`（已删除）的场景是：目标发送 `banner` 后执行 CloseWrite，然后继续读。
   - H2：客户端随后写入报错。
   - H3：写入返回成功，但目标收到 0 字节，数据被静默丢弃。
   - 原因是节点在下行 EOF 后关闭整条流。
   - 交接中"TCP 两端可独立半关闭"一句不准确，批复要求的反方向测试也没有做。
   - Go 的 H2 服务端无法在处理器返回前结束响应，Xray 也只给约 1 s 余量，所以这个方向不作硬性要求。但 H3 不能静默吞掉数据，文档也要改正。
6. **兑换连接的 TLS 指纹与业务连接不一致。** 兑换使用 Go 默认 TLS ClientHello，ALPN 只有 h2，与业务连接的 Chrome 指纹不同。
7. **邀请链接要靠 Python 手工拼装。** 节点 CLI 不能直接输出 `nexus://invite/v2#…` 链接或二维码，私人分享链路有缺口。
8. **`V2ErrorsTest` 不在 Gradle 里运行。** 它是 `main` 程序，`testDebugUnitTest` 实际执行 0 个用例，CI 也不会跑。

### 结论

M3 第 1 部分功能完整：合编引擎、邀请兑换、VPN 接入、阻断回退和界面都已就位，阻断门槛达标。上面 1–4 会直接影响真机验收和"强于现有协议"的目标，须在 M3 第 2 部分开头修复，修复后再安排真机测试。
