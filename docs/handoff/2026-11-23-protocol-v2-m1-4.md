# M1 收尾 · 私人节点分享

本轮按修订后的产品决定清除 V2 的流量计量和售卖能力。TCP 双向直接复制，UDP 按完整数据报转发。每次开流仍校验设备授权、到期、目的地址策略和节点资源限制。客户端传输 API 沿用 `607a3f8`。

## 数据和配置

节点仅创建 schema v4。users 只含 ID 与到期时间，另外三张表为 invites、devices 和 audit。旧实验库打开时报错并提示在新路径重建；保留旧文件，给新库中的设备重新签发邀请。备份继续在节点运行时使用 VACUUM INTO 并检查完整性，恢复需停机。

同真实账本路径的 Caddy 重载共享授权监视器，活动 H2/H3 TCP 流与 UDP 关联可以继续，新设备可以兑换。配置失败继续使用原配置。切换到独立新库时，旧库的最后一个 handler 释放引用并关闭旧流，设备后续按新库授权。仅在进程停机时执行停机断流。节点不再创建 `.owner` 文件。[账本和管理命令](../protocol/v2-node-ledger.md)

## 验收

新增的 H2、H3 停读回归使用同用户的两台设备。第一台持续向回显服务写入但不读取下载，确认传输已受流控后，第二台逐块写入并核对 20 MiB 回显。另有在线备份替换及 Caddy 实际 reload 回归。

规范分支 `protocol/v2-design` 的同名交接文档保存最终归档提交、Go 全量测试、雷电 0、60 对吞吐及 M2 开工申请入口。开发分支在正式采样前锁定，M2 的依赖和环境须另行批准。
