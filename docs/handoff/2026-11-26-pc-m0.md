# PC-M0 · Windows x64 客户端交接

基线 `827f128`。本机验收日为 2026-11-25（上海）。正式设计见[桌面设计](../desktop/design.md)。本地开发分支为 `v2/m0-transport`。

## 使用与构建

本机验收目录为 `E:\代理软件\验收包\PC-M0`。在有 WebView2 Runtime 的 Windows x64 上，保留两个 exe 同目录，运行 `nexus-desktop.exe`。首次粘贴有效的 V2 邀请并点「连接」，已登记过可留空。等显示「已连接」后，在需要代理的应用内指定 SOCKS5 `127.0.0.1:21808` 或 HTTP `127.0.0.1:21809`。点「断开」释放端口。端口已被占用时连接会失败。

从仓库根目录执行以下 PowerShell。Go 1.27.4、Python 3.11+、Rust/MSVC、固定 libXray 源码以及各模块的本地缓存须已准备好。下例使用本机已有缓存；其他机器替换路径即可。生成普通开发版，Tauri bundle 保持关闭。

```powershell
$env:Path = "E:\temp\toolchains\go1.27.4-win\go\bin;$env:USERPROFILE\.cargo\bin;$env:Path"
$env:GOTOOLCHAIN = 'local'
$env:GOPROXY = 'off'
$env:GOSUMDB = 'off'
$env:GOMODCACHE = 'E:\temp\toolchains\go-mod-r2'
$env:GOCACHE = 'E:\temp\toolchains\go-cache-r2'
$env:CARGO_TARGET_DIR = (Join-Path $PWD 'apps\desktop\target')
E:\.venv\Scripts\python.exe tools/build_desktop_core.py E:\temp\nexus-round5\libXray apps/desktop/target/debug/nexus-core.exe
if ($LASTEXITCODE) { throw "core build failed" }
cargo build --offline --locked --manifest-path apps/desktop/Cargo.toml
if ($LASTEXITCODE) { throw "shell build failed" }
```

`apps/desktop/core` 实现 CNG 和核心入口，`apps/desktop/src` 与 `ui` 管理窗口和子进程。Go 构建使用已固定的 Xray-core `676eaf66f8f0`、libXray `5a0f7d8d1c28`，复用 Android 的 V2 默认出站。已核对产物 build info 的 `windows/amd64`、`CGO_ENABLED=0` 及传输依赖。Android 原有 JSON 入口和 Java 绑定保留，双 ABI 离线 AAR 构建通过。此次没有新增第三方依赖。

## NexusLab 实测

Windows 客户端通过本机两个回环入口连接 WSL2 NexusLab 的隔离 V2 节点。实验使用 v2.0.1 Linux 节点、独立账本、IP 证书、带 SPKI pin 的一次性邀请及独立 Windows 配置目录。Windows 实际使用 Microsoft Platform Crypto Provider。目标仅为节点允许的实验地址。Windows 系统代理、TUN、防火墙、系统 DNS 和网卡配置均未改动。

| 项目 | 验收方法与结果 |
| --- | --- |
| H3 TCP | SOCKS5 CONNECT 和 HTTP 代理分别访问实验 HTTP 应答器。两次均收到 200，响应体与各自的随机请求值一致。 |
| UDP / DNS | 经 SOCKS5 UDP ASSOCIATE 返回的回环端口发送 A 查询。H3、H2 都收到事务 ID 匹配且地址为 `192.0.2.41` 的答复。先测普通 UDP 目标端口 34941，再测 NexusLab `127.0.0.2:53`，覆盖共享出站的 DNS 首包分支。 |
| H3 → H2 | H3 已成功处理业务后，实验中继只丢弃发往该节点实验端口的 UDP，TCP 仍通。在同一核心进程发起业务，1.837 秒后观测到 `ready:h2`。随后重复两种 TCP 入口和 UDP DNS 验收成功。 |
| 桌面窗口 | 实际 WebView2 窗口留空使用已登记身份，看到「已连接 / H3」。阻断后窄窗口显示「已连接 / H2」，入口和断开按钮可见。点「断开」恢复「未连接」。另一次在 H2 时直接关闭窗口，已观察到对应子进程退出。 |
| 复用边界 | Windows 只注册所需回环入站，Xray 的默认占位出站在启动监听前替换。现有 Android V2 出站逻辑直接用于两条线路。 |

在具有相同回显目标的实验节点上，下列检查可复用。先启动并连接桌面端；地址按实验节点实际配置替换。两个请求均强制经指定回环代理，同机代理环境变量里的排除项不会把实验流量导向其他入口。

```powershell
$tag = [Guid]::NewGuid().ToString('N')
$url = "http://127.0.0.2:34941/pcqa/$tag"
foreach ($proxy in 'socks5h://127.0.0.1:21808','http://127.0.0.1:21809') {
    $reply = curl.exe --silent --show-error --fail --max-time 10 --noproxy unused.invalid --proxy $proxy $url
    if ($LASTEXITCODE -or $reply -ne $tag) { throw "TCP receipt failed for $proxy" }
}
```

## Claude 评审

结论：**通过**。架构与设计文档可以作为 PC-M1 的基础。

复现：
- 在本机用同一命令重新构建 `nexus-core.exe`，大小同为 20,797,952 B。`go version -m` 与验收包只差 replace 指向的临时目录，依赖和版本一致。`cargo build --offline --locked` 通过。
- 核心的输入约定：保持 stdin 打开时，空邀请且无已登记身份、无效邀请都输出 `connecting` → `error` 并以 1 退出；首行不是 JSON 时直接输出 `error`。stdin 关闭即退出，与「EOF 即停止」的设计一致。
- 联网验收（H3/H2、UDP DNS、切换 1.837 s）采信本交接的记录和窗口截图，未重复搭建实验节点。

代码检查：
- 邀请只经匿名管道传入，不进入命令行和日志；Rust 侧以 JSON 编码写入，并拒绝换行和超长输入。
- CNG 密钥不可导出，优先 TPM；兑换前先保存请求 ID，响应丢失可用同一请求重试。
- `v2vpn.StartConfig` 和 `stage_client` 是对原有代码的原样搬移，Android 行为不变。

留给后续里程碑：
1. **M1 · 错误提示**：现在所有失败都显示「连接失败，请检查邀请、端口和节点」。需要按安卓的做法区分：邀请已被领取或过期、节点连不上、端口被占用。
2. **M1 · 端口占用**：21808/21809 被占用时直接失败。开启系统代理后，这个问题会更常见，需要自动换端口或给出明确提示。
3. **M1 · 品牌**：桌面界面还是 1.x 的绿色，应改成 2.0 的蓝色和 `docs/brand/nexus-logo.svg`。
4. **M1 · 身份清理**：每份邀请都会新建一把 CNG 密钥，目前没有删除入口。需要加「移除此设备身份」，同时删除密钥和记录。
5. **M3 · 发布构建**：二进制的 build info 带有构建机的临时目录，其中含本机用户名。正式包应在 CI 构建，或者把 replace 改成相对路径。
