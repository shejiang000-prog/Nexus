# 自研协议 UDP 关联复用

本地分支 `protocol/udp-mux`，基线 `a14ec74`。测试服务端均为回环或 WSL NexusLab 临时实例。Android 全程只使用雷电 `emulator-5554`。

## 协议和实现

旧客户端对每个非 DNS UDP 关联单独建立 udp1 连接。mux2 在一个经过 mTLS 认证的连接上混合承载 TCP 和所有 UDP 关联。每个 UDP OPEN 成功响应带 4 字节网络序关联号。关联号来自控制流序号，全连接生命周期不复用。正常大小的非空报文经带前缀的 DATAGRAM 发出，空报文和超过路径上限的报文走本流 u16 帧。未注册的关联号、过短或过大的 DATAGRAM 丢弃；队列满只影响对应关联。[字节格式与上限](../../PROTOCOL_SPEC.md)

传输层每连接维护一个 DATAGRAM 读取任务，每关联队列容量 16。流释放时移除映射，关连接时终止读取任务。服务端保留 4096 全局流和 256 条每连接双向流上限；mux2 UDP 另有 256 个注册项上限。DNS 空闲 10 秒，其他 UDP 空闲 60 秒。Android 的 `udp_flow` 本来就通过同一个 Connector 调用 open/packets，本次由共享客户端库接入新协议，沿用 Android 的 64 个 UDP 关联上限。

注册表在 mux2 连接上共享一份租约和一个撤销监听。数据双向分别计载荷字节；预留余额在判断额度时计入，避免尚未花完就误关闭连接。数据库慢路径只补充可退余额；调用任务获准转发时才扣减。连接撤销会终止当前 TCP 流和 UDP 关联并结算。Android 网络切换后重新认证，已经中断的数据由上层应用重试。

## 兼容矩阵

| 客户端 | 服务端 | 实际覆盖 |
|---|---|---|
| 新 | 新 | mux2，64 个同时打开的 UDP 关联；观察服务端 QUIC v1 Initial 的不同 SCID（重传去重），计数为 1。255 次逐字节回显，包括空报文和 1472 字节；一个关联主动关闭后，其他 63 个继续回显 |
| 新 | 基线 | 运行从 a14ec74 构建的旧服务端；非 DNS UDP 协商旧协议并正确回显短包、1472 字节包和空包 |

## 基准与复验

32 个并发关联，每格 672 个报文样本，两个版本 × 四个条件，共 5376 行。首回显 P50（基线 → mux2）：80 ms、无丢包 843.5 → 323.9 ms；80 ms、3% 766.8 → 324.1 ms；180 ms、无丢包 1066.6 → 724.0 ms；180 ms、3% 1131.0 → 724.7 ms。持续成功回显接近 RTT；3% 为每个方向的注入丢包率。[完整 P50/P95、丢包率与环境](../../BENCHMARKS.md) · [原始 CSV](../benchmarks/2026-11-22-udp-mux.csv)

构建基线客户端与服务端时使用 `git archive a14ec74` 的独立源码目录、独立 target 目录。新版运行 `cargo build --workspace --bins --examples` 后，以 `python tools/test_tunnel.py --bin-dir <新版目录> --baseline-dir <基线目录>` 重验；也可以设置 NEXUS_BASELINE_BIN。省略基线目录会明确跳过两项旧二进制覆盖。基准在两份代码树中使用同一测量程序，均为 release，命令见 BENCHMARKS.md。

## 验证边界

没有连接或升级真实 VPS，没有操作真机或其他模拟器。未测真实无线链路、电耗、Keystore 签名的独立耗时、256 关联极限压力或一小时生命周期。关联隔离用主动关闭验证，没有单独等待 60 秒自然超时。所有网络性能结论限于本次 WSL netem 条件。
