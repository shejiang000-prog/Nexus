## 域名预检与首签

|验收场景|观测结果|
|---|---|
|DNS 地址未配置到网卡，端口经 DNAT 回到主机|在独立网络和挂载命名空间中，将测试域名解析到未分配的文档地址，使用 nftables 做 DNAT。实际 HTTP 请求取得随机响应，内核 DNAT 规则计数增加，预检通过。|
|从节点无法回访域名|移除 DNAT 并使地址不可达。交互模式显示原因，确认后继续，拒绝则中止。无交互模式默认中止，加 `--skip-dns-check` 才继续。该参数不能绕过 80/TCP 监听冲突。|
|域名可回访，CA 明确拒签|用测试 CA 的拒签域名真实安装 V2。安装器报告 CA 拒绝该标识符，9 秒内回滚。没有遗留本次创建的文件、单元、服务账户或规则。单元回归另覆盖 CA 报告 DNS、连接、授权或限流错误，以及没有可确认原因时的提示。|
|域名可回访，CA 签发|在同一 NexusLab 用本地 CA 实装 V2、Reality、Hysteria2。三项服务均通过健康检查。短期证书在 17.408 秒后自动更新，两端新握手与磁盘上的新证书一致，原 QUIC 会话在等待期间的 8 次检查与换证后均返回 233。|

回访监听、随机路径和独立的随机响应只在安装前短暂存在。只向管理员给出的域名直接发送请求，回访不使用环境代理、不跟随重定向。健康检查还需在 180 秒总时限内验证 Caddy 实际出示的域名证书及协议服务。安装器仅从本次 Caddy 进程的相关日志提取 CA 问题类别。连接失败时，DNS、云安全组或 NAT 转发都是可能原因，须分项检查。公网首签、云厂商网络及默认 Reality 目标的实网评估留至 M4。

## Reality 会话策略

管理员执行 `compat disable USER reality`、`compat rotate USER reality` 或 `revoke-user USER` 时，默认重建共享入站。目标用户的旧 UUID 无法重新认证。其他 Reality 用户的旧连接也会断开，可用原配置重连。只有整节点换钥才要求其他用户重新导出链接。三个命令均接受末尾的 `--keep-connections`，保留已认证连接。先用保留模式禁用或撤销后，可再用默认模式断开留下的旧流。

有效的 v5 账本在事务内补充 Reality 入站重建修订号，已有 UUID、密钥及审计连续。重建要求和凭据变更原子提交，离线重启按当前账本恢复，同一修订重放可保留已经重连的设备。目标站提示建议优先选择与 VPS 同网络或同地区、支持 TLS 1.3 与 X25519 的站点。默认值仍为 `www.microsoft.com:443`。

在隔离网络内用锁定版本官方 Xray 和 Hysteria 客户端运行 `tools/verify_v2_compat.py`。以下时间自启动 CLI 起算，默认模式以两条实际 TCP 流读到 EOF 或 reset 为准，保留模式以持续回声为准。数值为本次观测。

|操作|目标用户 A 的旧流|另一用户 B 的旧流|B 的原配置|
|---|---|---|---|
|默认轮换 UUID|1.163 s 断开|1.163 s 断开|重连成功|
|默认禁用|1.203 s 断开|1.202 s 断开|重连成功|
|默认撤销已启用的用户|1.123 s 断开|1.123 s 断开|重连成功|
|保留连接撤销后，改用默认撤销|1.126 s 断开|1.126 s 断开|重连成功，再次撤销保留重连后的会话|
|保留连接轮换、禁用、撤销|三次分别在 4.252、4.197、4.208 s 时仍可回声|各次均持续可用|继续使用原配置|

三个保留连接用例均验证旧凭据无法新建 TCP 或 UDP 业务。整节点换钥时两位用户旧流在 1.224 s 内关闭。另验证两协议的两用户 TCP/UDP、离线轮换和重放、旧凭据拒绝及 mihomo 导出字段。
