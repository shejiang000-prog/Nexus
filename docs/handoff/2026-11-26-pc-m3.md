# PC-M3 · Windows 安装包、自动更新与构建

基线 `4210bca`，本地开发分支 `v2/m0-transport`。本轮使用当前 Android 版本 `2.0.1` 作本地打包验收。产物目录为 `E:\代理软件\验收包\PC-M3`。正式发布沿用 Android 的 `vX.Y.Z` 标签；例如 Android 升到 2.0.2 后，`v2.0.2` 生成 `Nexus-2.0.2-windows-x64-setup.exe`。本轮没有创建标签、推送或发布。

## 安装、服务与更新

- x64 NSIS 安装器使用固定的 `%ProgramFiles%\Nexus\app` 安装目录，创建开始菜单入口，缺少 WebView2 时运行随包微软引导程序。默认保留 `%LOCALAPPDATA%\Nexus\desktop`，包括订阅和设备记录。Wintun DLL 保持上游签名字节。
- SCM 服务名为 `NexusDesktopTun`，使用同目录的 `nexus-tun-helper.exe --service`，按需以 LocalSystem 启动。安装时记录受保护核心的 SHA-256。服务核对固定镜像、PID、管道和交互登录会话后复用原有整机、测试路由、恢复操作。普通连接无需服务。服务未安装或禁用时，核心使用 M2 的 UAC 助手；身份校验失败或会话占用时拒绝连接。
- 当前用户的壳通过固定 `--cleanup` 入口回收自己持有的 WinINet 和 TUN 状态。安装、卸载和更新需要已有客户端退出。壳启动时检查更新，也可点侧栏「检查更新」。发现更新后点击「安装更新」。更新从 GitHub Release 的 HTTPS `latest.json` 读取版本，由壳内置公钥验证安装器及签名中的版本。下载或验签失败时保留当前连接和已安装文件。通过验签后才断开连接、恢复设置并启动安装。
- 安装器在同一受保护根目录暂存新版本，保存旧 `app` 目录后切换。已安装的壳和核心共享打开 `maintenance.lock`，安装器在机器维护阶段独占该文件，防止清理之后又有进程开启连接。替换或服务注册失败会尝试还原原目录和旧服务。若机器在交换途中断电，再次运行安装器以完成记录中的恢复。其他登录会话仍有进程或待恢复的代理日志时，需要相应用户退出或恢复。
- 更新签名和 Windows Authenticode 签名各自独立。安装器、壳、核心和权限助手可用同一 Windows 证书签名；先签助手再将助手摘要编入核心。Wintun 沿用官方签名。用证书签完安装器后才生成更新签名和 SHA-256。

## 签名材料与未来 CI

本机已用锁定的 Tauri signer 生成更新密钥。目录 `%LOCALAPPDATA%\Nexus\Signing\desktop-updater` 仅授权当前用户与 SYSTEM。里面的 `update.key` 是带口令的私钥，`update.key.pub` 是可分发公钥，`password.dpapi` 是由当前 Windows 用户 DPAPI 加密的口令。只有公钥进入桌面配置。备份时同时考虑 Windows 用户的 DPAPI 恢复能力。

| 以后由维护者设置的 GitHub Actions Secret | 内容 |
| --- | --- |
| `TAURI_SIGNING_PRIVATE_KEY` | `update.key` 的原样文件内容（已由 signer 编码） |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | 在原账户下用 DPAPI CurrentUser 解密 `password.dpapi` 得到的口令 |
| `NEXUS_WINDOWS_PFX_BASE64` | 可选，Windows 代码签名证书及其私钥的 PFX 文件经 Base64 编码 |
| `NEXUS_WINDOWS_PFX_PASSWORD` | 与可选 PFX 配套的口令 |

本轮未配置任何 GitHub Secret。`release.yml` 的 Windows job 在 `windows-latest` 按 Android 标签、固定 libXray 提交、Go/Rust 工具链、Cargo.lock 和锁定工具摘要构建。生成的 Go 模块本地替换使用相对路径。缺少 Windows 证书时继续生成安装包并在 `windows-release.txt` 标记「未签名」。缺少更新密钥时也可取得手动安装的 workflow artifact；发布 job 在创建共享 Release 前要求有签名清单，以免已安装客户端遇到不可更新的新版本。

Windows artifact 包含安装器、`WINDOWS-SHA256SUMS.txt` 和代码签名说明；配置更新密钥后还包含 `.exe.sig` 和 `latest.json`。发布 job 校验构建端输出的清单摘要及所有文件，随后与 Android 资产放入同一 Release。固定工具、签名者与许可见 [依赖记录](../../DEPENDENCIES.md) 和 [第三方许可](../../THIRD_PARTY_LICENSES.md)。

## 本机快测

| 项目 | 结果 |
| --- | --- |
| 安装包 | Release x64 壳和最终配套核心、助手经 Tauri bundler 生成 NSIS 安装包。最终 14,983,517 字节，SHA-256 为 `adea72ef2339d2c57b5884070ca11866af5f0236b3c1374cc253c229873ab23d`。解包逐字节比对了三个程序、官方 DLL、三份 Wintun 许可、WebView2 引导和新增许可，并校验交付目录的摘要。此验收包未作 Authenticode 签名。 |
| 服务与信任检查 | 普通权限运行 `--test-tun`，核心、权限助手与 DNS 保护测试通过，包括拒绝用户可写路径和与安装不匹配的 SCM 配置。Go 二进制的 replace 项已检查为相对路径。 |
| 更新 | 实际 updater 插件通过回环 HTTP 取合成清单和包，用测试公钥接受正确签名并拒绝篡改包。实际桌面窗口检查了发现更新、中文拒签提示及窄窗口深色布局，测试 `--cleanup` 在隔离目录返回成功。 |
| CI 产物 | 本地验证 Windows job 和与发布 job 的依赖关系；用临时测试密钥签合成文件并核对有版本绑定的签名、清单和所有文件的 SHA-256。生产配置公钥与本机生成的公钥文件一致。 |

当前登录令牌未提权。本次没有执行真实安装、卸载或服务注册，也未启用系统代理或 TUN。没有修改本机路由、DNS、防火墙，未运行 GitHub 托管 job。真实服务接入、WebView2 缺失时的引导、安装回滚和卸载恢复留待下列验收。

人工审阅了 Program Files 权限、SCM 调用方认证、维护锁、卸载等待和整包回滚。Codex Security 差异扫描未识别本地工作树的 HEAD，没有生成插件报告。

## Claude 与用户的安装验收

1. 在可提权的隔离 Windows 机上记录当前代理及网卡基线。用普通身份从本地包启动安装，在系统提示时由用户同意 UAC。缺少 WebView2 的镜像另核对微软引导结果。启动后**保持断开**，核对开始菜单、应用版本、Program Files 的 ACL、三份可执行文件和原版 Wintun。
2. 用 SCM 只读查询核对 `NexusDesktopTun` 的固定路径、LocalSystem 身份和按需启动设置。免 UAC 的真实 TUN 连接、吞吐、IPv6 与切网沿用 M2 五步单独验收，须再征得用户同意。
3. 在隔离机用测试公钥构建的两版安装包做一次更新，并模拟服务注册失败，核对旧版壳、核心、助手、快捷方式和服务成套保留。关闭客户端后卸载，确认服务和安装目录消失、原用户数据保留、代理和网卡基线一致。Windows「已安装的应用」可以在 NSIS 自复制引导之后先返回，请以实际卸载窗口结束和上述检查为准。不要为验收卸载共享 WebView2 或 Wintun 驱动。
