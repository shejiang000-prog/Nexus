# M1 第 3 部分 · 额度账本与恢复

开发分支 `v2/m0-transport` 使用 schema v3。本轮变动集中在 `v2/server`、节点管理 CLI、集成测试、双 ABI 构建脚本及 `v2/go.sum`。客户端传输 API 沿用 `607a3f8`。完整计量口径、上界、命令和备份步骤见[节点账本](../protocol/v2-node-ledger.md)。

## 运行时与构建

用户的所有设备共享一份至多 8 MiB 的租约。TCP 部分写按返回字节计入，UDP 完整包按有效载荷计入。6 个并发写入者的测试实际写出 491,521 字节，与配置额度一致。H2 和 H3 独立节点用例让两台设备的 TCP 和 UDP 竞争同一限额，并验证耗尽及跨进程置零后的断流与新流准入。

原先每条短流结束都同步结算，50 设备回归让 SQLite 写锁竞争导致撤销返回 SQLITE_BUSY。现在流结束按用户在 25 ms 窗口内合并结算。另在 Caddy 开始停机时关闭账本业务，避免在默认无限宽限期内等待永久 CONNECT。

AAR 用一次 gomobile bind 合编 android/arm64 和 android/amd64，逐个检查原生库依赖版本、替换路径和校验和。移除 8 个已替换版本的 16 条旧校验记录。清理后的离线 prepare、双 ABI 合编和 Debug 测试包构建均通过。arm64 用静态检查验收。

## 恢复演练

独立节点保持 TCP 活动流，用户额度 1,048,576 字节。发送 4 字节并读回回显，周期结算为 8 字节。再发送并读回 1 字节，此时活动租约仍包含 2 字节未结算用量。

|场景|观察结果|
|---|---|
|SIGKILL 后从原库重启|活动租约转为 frozen，已用量按 1,048,576 字节显示。对账后已用 8 字节，再次对账没有新增流水。|
|带活动流在线备份、停机、换库、重启|副本保留 active 租约和 8 字节检查点。源库正常关闭时结算为 10 字节。移开旧库及其 SQLite 附属文件、换入副本后，恢复到备份点并按全额冻结。|
|恢复核对|用户、额度、设备和备份点之前的审计一致，冻结及对账后共 8 条连续审计。旧邀请无法用新密钥兑换。原设备能使用释放的余额继续回显。|
