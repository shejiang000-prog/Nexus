# V2 M1 第 2 部分 · 账本、管理命令与冻结版验收

开发分支 `v2/m0-transport` 的账本实现提交为 `75ac454`，AAR 校验和与替换路径检查为 `23cb0cb`，规范分支为 `protocol/v2-design`。传输接口沿用 `607a3f8`。测试使用 NexusLab、临时账本、合成设备，以及雷电实例 0（emulator-5554）。所有提交仅保存在本地。

## 账本和运维

旧监视器把读错误当作全员撤销。旧代码在默认 SQLite 等待设置下复现 3 s 锁误断；在测试句柄上将 busy_timeout 固定为 100 ms，600 ms 和 3 s 两个正式回归均报未撤销流遭关闭。修改后两组都通过。独立事务在锁内写入撤销，提交前活动流仍可用，提交后目标流在 1 s 内关闭，另一设备保持连接。

节点启用 WAL。监视器用独立读连接，每 150 ms 检查数据版本，发生提交才重建授权快照。每次登记流均检查缓存中的设备和账户期限。普通读错误按 300 ms 退避；连续失败 30 s 进入故障状态。权限异常、超时断流、权限恢复后重新准入、账户到期和 v1 审计迁移都已测试。缓存重建成本随设备数增长，此次负载覆盖 50 台持续开流设备。管理语法及故障处理见[节点账本文档](../protocol/v2-node-ledger.md)。

用户创建、发邀请、兑换、实际撤销均与审计原子提交。管理命令可在其他进程运行。最终全量 race 验收中，从发起 CLI 撤销到节点的活动 TCP 与 UDP 均结束，H2 为 251.34 ms，H3 为 261.40 ms。期限精度为秒。

最终实验在同一节点上让 50 台独立设备持续通过复用的 H2 连接发起 TCP 开流；每设备完成回显后再开下一流。穿插另外 8 次兑换及跨句柄撤销，另有 8 个并发客户端提交共 128 个针对随机令牌的有效自签名请求。计时从 DialTCP 前至收到首字节回显。共 13,623 次，P50 10.103 ms、P99 43.122 ms，全部成功，误判未认证 0 次。8 次撤销中的最大时延为 174.449 ms（从调用撤销起计，包含提交）。这是本机回环实验结果。

## 依赖、AAR 与互操作

桌面 uTLS 对齐到 `v1.8.3-0.20261108164504-a13c59ffe98b`。合编所用 go-brrr 为 v1.3.1，Go 官方 x/net v0.62.0、x/crypto v0.58.0、x/sys v0.49.0、x/text v0.43.0、x/sync v0.24.0。x/term 在 libXray 模块图中选中 v0.47.0，节点由 Caddy 引用。锁定信息见开发分支的 v2/go.mod、v2/go.sum 和 THIRD_PARTY_LICENSES.md。本地模块缓存可复用，唯独 x/term 缺 zip。通过 Go 模块代理获取该已批准版本，开启 sum.golang.org 校验，结果写入 go.sum。

合编完成后、发布输出文件前，逐个读取 AAR 内原生 Go 库的 build info，与 v2/go.mod 核对 uTLS、apernet/quic-go、x/net。本次构建目标 android/amd64；x86_64 原生库的三项版本一致，apernet/quic-go 为 `v0.65.1-0.20261109005002-2895f039137a`，源自既有本地补丁。含校验和的相关 Android 模块记录均与 v2/go.sum 一致。其他 ABI 未验证。

桌面与安卓使用默认配置分别采样 H2、H3 各 50 次。按 M0 第三部分的口径，与同一 Chrome 157 参考集比较 JA4、密码套件、扩展集合、组、签名序列、锚摘要，以及 H3 传输参数及其值。对 GREASE 使用同轮规则，对随机顺序按集合比较。四组均 50/50 匹配。安卓由合编库在 100 个新连接上完成签名及 UDP 回显，实验节点侧在内存中解析握手。规范分支的 `docs/benchmarks/v2-m12-hello-fields.csv` 仅含解析字段。Chrome 对照来源为 M0 第三部分留存样本，本轮未另行采集 Chrome 数据。

雷电三项 instrumentation 均返回 -1。M0Check 验证 4、0、65507 字节的 UDP 回显与解析/保护回调；CatalogCheck formats 验证 25 个格式样例及 3 类用量元数据，security 用例通过。测试后两个自装包卸载成功，雷电实例 0 状态已确认为关闭。

## Claude 评审

评审对象：开发分支 `75ac454`、`23cb0cb`、`311f6c4`，规范分支 `68c8e8f`、`7bacb00`。结论：**本轮 A 至 E 通过**，下列小问题留到下一轮修。

**独立复现（NexusLab，从 `311f6c4` 的 git archive 构建，GOPROXY=off）**

- `prepare_v2.py` 校验与打补丁成功，节点构建成功，`go vet ./...` 通过；源码中已无 http2legacy、xconnect、GODEBUG。
- 带独立节点的 `go test -race -count=1 ./...`：9 个包全部通过（server 37 s，含 600 ms / 3 s 锁与 30 s 故障用例）。
- 评审自写用例：另一进程用 `locking_mode=EXCLUSIVE` 加 `BEGIN EXCLUSIVE` 试图独占 WAL 账本。节点打开期间对方等 5 s 后得到 SQLITE_BUSY，拿不到锁；节点活动流未断，Lookup 正常。上轮复现的“短锁误断全员”已不存在。在 WAL 下，外部进程无法挡住节点的读连接，读故障实际只来自权限、文件身份或 I/O 错误，这些由 Codex 的 chmod 用例覆盖。
- 吞吐四格用独立脚本复算（统计量为中位数差除以竞品中位数，按配对编号重采样 10,000 次，取第 250、9,750 项；每格编号 0–59 齐全，无失败）。点估计与交接表逐位一致。区间因随机数实现不同而略有差别：hy-default 1% [−2.197%, +0.256%]、5% [−2.083%, +0.935%]；box-tuic 1% [−1.859%, +0.986%]、5% [−1.859%, +1.179%]。下界都远高于 −5%，**四格通过**。
- `v2-m12-hello-fields.csv`：四组各 50 条。桌面与安卓的 H2 JA4 都是 `t13d1517h2_8daaf6152771_cb7bf5808d99`，H3 都是 `q13d0312h3_55b375c5d22e_178839b6cec1`；密码套件、组、签名序列、锚摘要在每组内唯一且跨平台相同。H3 传输参数每条都不同，原因是 Chrome 式参数乱序与 GREASE，与 M0 第三部分按集合比较的口径一致。
- go.sum：go-brrr v1.3.1 的 h1 为 `EwaJUzRI…hF1w=`，与批准时核对的一致；x/net v0.62.0 等官方模块条目齐全。

**代码审阅要点**

- 读连接 + `data_version` + 整份快照替换的思路正确。版本号在查询前读取，若查询期间有新提交，下个周期会再重建，不会漏掉撤销。`register` 与快照替换在同一把锁下，鉴权和登记之间的空窗已关闭。
- 读故障期间沿用旧快照，最长 30 s。文档已说明“故障期间不保证跨进程撤销 1 秒内可见”。实际影响有限：权限或文件身份异常时，管理命令本身也打不开账本。
- 兑换：先做只读预检，再开 `BEGIN IMMEDIATE`，事务内复核，顺序正确。限流先于读取正文，超限走回落站点，与未认证请求的表现一致。
- 撤销时延口径变了。上轮 108/112 ms 是在同一进程内调用；本轮 251/261 ms 从启动 CLI 进程计起，包含进程启动和打开数据库。50 设备负载下，在同一进程内撤销最大 174 ms。都在 1 s 目标内。
- x/term v0.47.0 是经 Go 模块代理并开启 sum.golang.org 校验下载的，属于“优先用本机缓存”这条批准的范围。

**待修（不阻塞本轮）**

1. `ledger DB revoke` 遇到不存在的设备 ID（例如输错）时静默返回 0。应对“设备不存在”报错并返回非 0；对已撤销设备可以提示后返回 0。
2. `create-user` 接受已经过去的到期时间（`invite` 会拒绝）。两者应统一拒绝。
3. 兑换限流按 IPv6 /128 计数，攻击者轮换地址可以绕开每地址上限。只跟踪 4096 个地址，本身并不限制总量。建议 IPv6 按 /64 聚合，并加全局每秒总上限。
4. AAR 构建只做了 android/amd64，真机是 arm64-v8a。需要补 arm64-v8a 的合编和 build info 核对（静态检查，不需要设备）。
5. 冻结吞吐用的是 `c7806b0`，即 uTLS / x/net 对齐之前的代码。H3 数据面不经过 x/net，本轮结论可以接受；发布前的正式门禁须在发布候选上重跑。
6. go.sum 残留旧版本条目（x/crypto v0.57.0、x/net v0.60.0、andybalholm/brotli v1.0.6 等），整理即可。
