# M3 第 2 部分 · Android 私人节点

开发基线 `2d6645c`，规范基线 `c8370c3`。工作始于 2026-11-23，测量均为雷电实例 0 与 NexusLab 私有节点之间的结果。本文记录每轮候选、条件和失败样本，以首次成功的应用 TCP 回声作为切换完成时刻。

## 授权、续期与健康请求

Android 在开始连接、切换底层网络、回到前台或业务返回认证错误时向当前承载确认授权。新节点的认证回执携带 `Nexus-Account-Expires`；界面刷新本地记录。普通网站的 200 或 403 本身不能确认设备身份。节点的 H2、H3 未认证 GET/HEAD 与同站不存在路径的状态、头和正文/长度一致。已认证连接上的普通 GET 也必须单独出示证明才取得健康对象。认证和健康对照均不更新“最近业务”的时间。

- 独立节点 `TestAuthenticatedHealthAndRenewal` 覆盖 H2/H3 和到期后的续期。另测 H2/H3 × 撤销/到期四种组合，下一次真实业务和随后确认都返回错误 3，Android 清除自动恢复记录。旧节点若提供公开的健康文件，兼容分支只接受同连接上真实 CONNECT-UDP 的肯定确认；旧节点的出口策略须允许该目的地址。
- `tools/verify_android_v2_lab.py ADB dev.nexus.lab.m0 FIXTURE --phase expiry` 在真实模拟器将系统时钟前移 12 小时，节点账户原期限为 8 小时。已领取设备仍可连。隔离账本延长 24 小时后，正常业务刷新了界面上的到期时间，同一设备断开再连通过。管理员操作使用实验室 SQLite 事务模拟，目前管理 CLI 没有单独的续期指令。
- 首次测试发出认证 HEAD 后未到达本地 TCP 回显目标，修正测试的全局路由配置。第二次应用验收通过，驱动在恢复时间时差约 8 秒。最终按客体原始 elapsedRealtime 锚点恢复，第三次应用及驱动均通过，用时 5.37 秒，恢复误差 0 秒，自动校时状态与测试前一致。没有修改宿主机时钟。

## Android 承载选择

每个物理网络使用自己的 Client。H2 上仅在最近 30 秒有业务、屏幕亮且不在 Doze 时启动 H3 回探，失败按 30、60、120、240、300 秒退避。熄屏可取消正在进行的回探。节点空闲 40 秒的独立试验中没有新握手，下一次真实业务触发一次新签名和 H3 建连，11 ms 收到首个 TCP 回声。H3 没有主动 QUIC keepalive，默认闲置超时 30 秒。H2 使用 Go 的 TCP keepalive，空闲 15 秒，间隔 15 秒，未应答上限 9 次。内核保活、应用层请求、UID 唤醒闹钟以及进程线程调度分开计数。模拟器不能测量真机蜂窝射频的唤醒次数。既有兼容核心每秒还有一次本地 `Os.poll` 超时检查。

## 真机验收步骤

验收包的应用 ID 为 `dev.nexus.qa.m32`。由机主在获准使用的测试节点上执行以下步骤。

1. 安装验收包，打开「节点 → 添加节点」，从管理员领取两个一次性邀请。分别粘贴、扫码，核对节点地址并确认。设备页记录设备 ID 简写和到期日。IP 节点应显示「IP 模式」，整个流程没有指纹输入步骤。
2. 在 IP 节点上连接 VPN，分别打开有回显的 TCP 和 UDP 测试。由节点管理员仅阻断这个节点的 UDP 端口，记录冷启动及运行中首个新 TCP 回声耗时。解除阻断并继续业务，检查 H3 恢复以及原 H2 TCP 下载能否完成。
3. 有 Wi-Fi 和真实移动数据时，分别执行 Wi-Fi 与移动数据互换、开关飞行模式、断网 30 秒后恢复。每类十次，以首个成功 TCP 回显计时。使用有唯一编号的消息，服务端据此核对重复递交。
4. 保持后台空闲并熄屏十分钟，再解锁发起一条业务。对照节点请求计数与手机电池统计。有 StrongBox 的设备由机主确认密钥硬件级别。
5. 管理员延长账户有效期后重新连接，核对到期日刷新和设备 ID 不变。随后撤销该设备，再触发一次认证，确认停止重试并给出中文原因。最后用已有第三方订阅验证一次正常连接。

## 构建与交付

- NexusLab 离线运行 `python3 tools/prepare_v2.py "$OUT/mod"`。在 `v2/` 设 `GOFLAGS="-modfile=$OUT/mod/v2.mod -mod=readonly"`，执行 `go build -o "$OUT/node" ./cmd/nexus-node`、`go vet ./...`、`NEXUS_NODE_TEST_BINARY="$OUT/node" go test -race -count=1 ./...`。合并实现全部退出 0，integration 用时 12.771 秒，server 38.228 秒。
- `tools/build_v2_aar.py --lab LIBXRAY LAB_AAR` 仅供长稳计数。真机验收使用独立生成的普通 AAR。两次均离线从锁定源码合编 arm64-v8a、x86_64，每个 libgojni.so 均核对 Go build info 与 go.sum。Linux 节点按相同补丁源码交叉构建两种架构，Android 经已核验的 SSH 主机密钥上传，并比对上传文件的 SHA-256 后才运行。
- `:app:testDebugUnitTest` 实际执行 `V2ErrorsTest.mappedErrorsExplainCauseAndRetryPolicy` 一例，跳过 0、失败 0。JUnit 与 Hamcrest 取自已锁定的 Gradle 8.14.3 安装包。Debug 应用、instrumentation 与独立业务探针均构建成功。
- 真机包以 `-PnexusDeviceAcceptance=true -PnexusV2Aar=普通合编AAR :app:assembleDebug` 构建。包名 `dev.nexus.qa.m32`，桌面名称「Nexus 验收」，版本 1.0.1（10001），两个 Android ABI 共 120,285,052 B，包含可经 SSH 上传的两个 Linux 节点。APK 签名通过核验，交付文件 SHA-256 为 `1f96a3e679cb6de7aa4dd7dd88ab024c464a12e3dc5b3262e8b040ce9455f88f`。旧工具 aapt 第一次直接读取含中文的绝对路径报编码错误，改用源码树内同一 APK 的 ASCII 路径读取清单，并核对复制前后摘要相同。

默认 IP 安装在真实 systemd 启动了两个服务，V2 使用 443/TCP+UDP，Reality 使用 8443/TCP。彻底卸载并重装生成了新的 SPKI。已验证 Android 的 NodeManager 通过临时 SSH/SFTP 将 APK 内的对应架构节点上传至 NexusLab，核对 SHA-256 后重复执行同参数安装，并取得带指纹的有效一次性邀请。夹具只使用临时 SSH 密钥，完成后已回收，系统必需的 V1 实验服务保持运行。实验室没有 qrencode，真实 CLI 输出可复制链接，另有测试验证可选绘制程序从标准输入读取邀请。

IPv6 在 NexusLab 通过真正绑定 `::1` 的节点与目标验收。先兑换，重启后用原设备在 H2 和 H3 分别完成 TCP 与 UDP 回显。换证后原客户端返回 2。IPv4 与 IPv6 独立节点用例合计 1.67 秒。Android 的粘贴和扫码回传都进原确认窗，只显示节点地址；实际卡片同时显示 IP 模式、承载与到期时间。部署表单的可选域名、密码及原操作路径已在雷电界面核对。

### 复现 C 切网与两小时采样

用 `tools/build_v2_aar.py --lab` 从锁定源码离线生成只有实验室 APK 才有 Go 协程计数的 AAR。安装独立 ID 的 Debug、配套 instrumentation 与授权 VPN 的 probe。以另一个新目录开独立域名夹具。

```sh
python3 tools/android_v2_lab.py "$NODE" "$XRAY_ZIP" "$BIND_IP" "$WORK/stability" --echo-ip 192.0.2.86
# 另一个 NexusLab 终端
for phase in airplane handover offline soak; do
    python3 tools/android_v2_lab.py issue "$NODE" "$WORK/stability" "$phase.json"
done
```

在 Windows 使用相应的单次 JSON 为每个阶段运行一次。

```powershell
python tools/verify_android_v2_lab.py $ADB dev.nexus.lab.m0 $CFG --phase airplane --ld-shell $LD
python tools/verify_android_v2_lab.py $ADB dev.nexus.lab.m0 $CFG --phase handover --ld-shell $LD
python tools/verify_android_v2_lab.py $ADB dev.nexus.lab.m0 $CFG --phase offline --ld-shell $LD
python tools/verify_android_v2_lab.py $ADB dev.nexus.lab.m0 $CFG --phase soak
```

三种切网各 10 次。以恢复动作前的 Android 单调时钟为起点，以新建真实 TCP 流收到第一个匹配回声为终点。每次破网前，旧持久 TCP 上发出一条无 ACK 的操作，合成目标独立统计该操作；恢复后向同一目标查询，判断是否仅交付一次。Wi-Fi/蜂窝切换还要求 ConnectivityManager 上报独立 CELLULAR Network、Wi-Fi 接口已下线且 TCP 回声通过。30 秒断网从首次观察到实际请求失败开始计时。始终通过原生雷电命令通道驱动切网测试，恢复 Wi-Fi、移动数据及飞行模式的初始设置。

长稳保持同一 VPN 服务，前 60 分钟每隔约 15 秒发 TCP 回声、UDP 回声和完整 4 MiB 下载，每次校验内容；后 60 分钟没有业务请求。每 5 分钟读应用与节点的 PSS/RSS、fd 和真实 Go goroutine 的数量。节点通过独立 Unix admin socket 读 pprof 计数，通过进程 fd 对应目标端口核对 TCP/UDP 数量。仅记录数字。关闭 VPN 并等待 10 秒后再取样，核对目标连接全部释放。Android 数值在 instrumentation 结果，节点数值写入 `$WORK/stability/node-samples.jsonl`。用 `$WORK/stability/stop` 停止夹具。
