# Windows PC-M1 交接

基线 `4c33413`，本地开发分支 `v2/m0-transport`。已按 [PC-M0 的 Claude 评审](2026-11-26-pc-m0.md#claude-评审) 处理端口、品牌、错误反馈和身份清理。下述快测在 2026-11-25（上海）完成。真实 WinINet 接管留待 Claude 取得用户同意后验收。

## 使用

本机验收包在 `E:\代理软件\验收包\PC-M1`。将 `nexus-desktop.exe` 和 `nexus-core.exe` 放在同一目录，运行桌面程序。首次连接粘贴 V2 邀请，之后可留空使用已登记身份。默认选中「系统代理」和「绕过大陆」，开关及模式选择保存在本地。**与 v2rayN 并用且希望保留其系统代理时，在点「连接」之前先关闭「系统代理」。** 之后在目标应用中填写窗口显示的实际回环端口。

| 功能 | 行为 |
| --- | --- |
| 系统代理 | 核心确认可用后，壳将当前用户的 WinINet HTTP/HTTPS 代理指向实际 HTTP 端口。开关支持连接中切换。写前保存所属连接、原参数及预期写入值，记录每个写入阶段；关闭开关、断开或正常退出时恢复。壳崩溃后，下次启动先恢复。发现外部更改则保留现值并提示。 |
| 分流 | 断开时选「绕过大陆」或「全局代理」。前者依据与 Android 共用的固定域名、IPv4/IPv6 和 LAN 规则走直连或 V2，另识别 `localhost`、`.local`、`.home.arpa`。后者将送进本机代理的请求全部交给 V2。 |
| DNS | 分流逐条检查送入代理的 53 端口 UDP/TCP 查询，国内名称发给活动物理网卡所配置的解析器并绑定该接口。其他或无法安全分类的查询强制走 V2，即使目标解析器地址属于直连网段。连续查询和同一 SOCKS UDP 关联切换目的地会重新判断。应用自己发到代理入口以外的 DNS 由应用和操作系统管理。 |
| 端口与错误 | 默认回环端口 SOCKS5 21808、HTTP 21809，各自遇到占用时自动找空闲端口，实际监听成功后再上报。错误管道只传固定错误码；拒绝兑换统一显示「邀请已被领取、已过期或已被撤销，请向分享人要一条新的邀请。」节点不可达、本机端口不可用、设备密钥丢失和邀请格式错误有独立中文提示。节点端协议保持现状。 |
| 身份与界面 | 2.0 窗口与应用图标使用 `docs/brand/nexus-logo.svg` 的蓝色品牌。主页仅显示掩码和端口。确认移除时在锁内核对原身份，删除 CNG 密钥、本地登记记录及当前引用。其他身份保留；仍被任一连接使用的身份会拒绝删除。未实现的页面显示「暂未支持」。 |

WinINet 使用按连接的配置接口，快照保留原代理、绕过列表、PAC 与自动发现状态。日志位于当前用户的 `%LOCALAPPDATA%\Nexus\desktop\wininet.journal`，恢复完成或确认第三方已接管后清理。多窗口通过独占文件锁协调。WinINet 的读取与写入是独立调用，客户端在每步写前后重读配置；其他软件同时写入的瞬间仍存在操作系统接口的竞态窗口。[Microsoft WinINet 配置项](https://learn.microsoft.com/en-us/windows/win32/api/wininet/ns-wininet-internet_per_conn_optionw)

## Claude 的真实系统代理验收（需先获得用户同意）

1. 与用户约定可短暂切换代理的时段和恢复方式，优先用独立 Windows 测试账户。记录当前用户的代理启用位、地址、绕过列表、PAC 和自动发现设置；有 v2rayN 时确认其期望状态。
2. 保持「系统代理」开启，连接实验节点；核对 Windows 当前用户 HTTP/HTTPS 代理端口与窗口中的 HTTP 端口一致。用遵循系统代理的应用访问实验回显，再关闭开关，核对原设置恢复。
3. 再次启用，分别验证「断开」和正常退出后均恢复原值。然后在连接中只结束桌面壳进程，重新启动 Nexus，核对启动恢复；无需重新连接即可完成恢复。
4. 经用户同意，模拟其他代理工具在 Nexus 接管期间写入一组可识别的配置。断开 Nexus；再做一次崩溃重启场景，核对两次均保留第三方现值。结束时按用户约定恢复其工作配置，验证 v2rayN 可用。

## Claude 评审

结论：**需要小修一轮**，主体通过。

复现：`build_desktop_core.py --test-routing` 分流对照测试通过，`nexus-core.exe` 22,097,920 B；`cargo test` 1/1 通过（WinINet 接管、崩溃恢复、部分写入、第三方更改）；`cargo build` 通过。联网和窗口验收采信本交接记录。

做得好的：WinINet 逐字段写入、每步前后重读核对、日志记录两个可能状态，崩溃在任意一步都能识别并恢复；只在当前值仍是我们写入的值时才恢复。断开和退出时同步恢复，不依赖后台线程。拒绝兑换的文案与 Android 一致。端口冲突自动换端口并上报实际端口。

必须修：
1. **全局模式下局域网和本机地址会被送到节点。** 系统代理的绕过列表被设为空，全局模式又没有任何路由规则，于是 `192.168.x.x` 路由器后台、NAS、打印机、`localhost` 开发服务等经系统代理进入核心后全部发往 V2 节点，结果打不开（Chrome/Edge 只隐式绕过回环，不绕过局域网）。修法：
   - WinINet 绕过列表使用常见的本地列表（与 v2rayN 一致）：`localhost;127.*;10.*;172.16.*`…`172.31.*;192.168.*;169.254.*;<local>`，恢复时仍按原值复原。
   - 核心在全局模式也加一条规则：回环、私有、链路本地地址和 `localhost`/`.local`/`.home.arpa` 走直连，供直接填 SOCKS/HTTP 端口的应用使用。

建议本轮一起改：
2. **SOCKS UDP 补丁把每个目标地址拆成独立的 UDP 关联。** 原来的 cone 模式下，同一个 SOCKS UDP 关联里的所有目标共用一条出站，节点侧也只用一个源端口；现在每个目标各开一条 V2 UDP 流，节点侧端口各不相同，NAT 类型从锥形变成对称型，影响游戏、语音和 P2P 打洞。拆分只是为了让国内/国外目标分别走直连和 V2。改成按路由结果分组即可：用路由器先判定目标对应的出站标签，同一个标签共用一个 dispatcher（全局模式只有一个）。

后续：
- 真实系统代理验收按交接里的步骤做，但不新建 Windows 账户。征得用户同意后，在用户本机记录当前代理设置（导出 Internet Settings 注册表项作为保险），连接 Nexus 接管、断开、结束进程后重启，核对 v2rayN 的设置被原样恢复。
- 订阅导入留到 PC-M1-2。

## 小修

基线 `eefa3b3`。Windows x64 桌面壳和核心均已离线构建，配套验收包位于 `E:\代理软件\验收包\PC-M1-小修`。本轮只使用指定端口、替换存储和 NexusLab，未写入本机系统代理、TUN、防火墙或网络配置。

1. **本地地址直连，通过。** WinINet 绕过列表包含 `localhost`、`127.*`、`10.*`、从 `172.16.*` 到 `172.31.*` 的每一项、`192.168.*`、`169.254.*` 和 `<local>`。替换存储测试核对了完整清单、按所有权恢复原值、保留第三方修改，以及旧版空绕过日志在恢复中再次中断后仍可恢复。核心的全局模式对 IPv4/IPv6 回环、私有、链路本地单播和 `localhost`、`.local`、`.home.arpa` 直连。显式发给代理的 53 端口查询沿用原 DNS 策略，全局走 V2，分流按查询名判断。NexusLab 快测在全局模式分别经 SOCKS5（21808）和 HTTP（21809）访问 `127.0.0.3`，两次都收到 Windows 回显，节点对该目标的 CONNECT 计数为 0。
2. **SOCKS UDP 已按出站标签分组，节点跨目标同源端口验收未通过。** 核心逐包查路由，同一 SOCKS UDP 关联内同标签复用 dispatcher，并保留各包的目标和应答来源。NexusLab 在一个关联内交替访问两个按境外规则路由的隔离回显目标和两个 Windows 回显目标，所有应答均与各自请求匹配。分流 DNS 快测在同一关联内依次查询国内、国外、国内名称，两个国内查询均由替换的物理 DNS 应答，国外查询走代理。

   | 模式 | 节点侧目标 A / B / 再次 A 观察到的源端口 | Windows 直连目标 C / D 观察到的源端口 |
   | --- | --- | --- |
   | 全局 | 48022 / 45717 / 48022 | 54710 / 54710 |
   | 绕过大陆 | 47964 / 34254 / 47964 | 54718 / 54718 |

   现有 V2 客户端按目标建立 CONNECT-UDP，节点为每个 CONNECT 创建独立的 UDP 套接字。跨目标复用节点源端口需要节点支持。Windows dispatcher 分组只解决客户端链路复用和直连端口复用。本轮未改节点或协议。
