# M3 第 3 部分 · Android 小修

开发基线 `d34189b`，规范基线 `e081239`。设备验收使用雷电实例 0 和 NexusLab 私有节点。

## 复现与测量口径

- 实验室版从锁定源码离线合编。在 Windows 设置 `docs/ANDROID.md` 中的 Go、Python 和模块缓存，用 `tools/build_v2_aar.py --lab LIBXRAY AAR` 生成 AAR，再构建 Debug 与 androidTest。首次调用 Gradle 时 Windows 的默认 python 别名返回 9009，改用已有解释器的绝对路径设置 `NEXUS_PYTHON` 后通过。
- 在 NexusLab 运行 `python3 tools/android_v2_lab.py NODE XRAY_ZIP LAB_HOST WORK`；各阶段用 `python3 tools/android_v2_lab.py issue NODE WORK PHASE.json` 发出独立的一次性邀请。用 `python tools/verify_android_v2_lab.py ADB dev.nexus.lab.m0 FIXTURE --phase PHASE` 运行 `soak`、`idle-h2`、`expiry`。
- 长稳保持同一 VPN 进程。初次回声后先空闲 35 秒，确保以已连接且空闲的进程作为起始基准，避免把建连中的短期协程计入基线。前 30 分钟每轮校验 TCP 回声、UDP 回声及完整 4 MiB 下载，轮间休息最多 15 秒，后 15 分钟没有业务。每 5 分钟从 App 本地和节点的本地管理套接字采样。停止 VPN 后等待 10 秒，读取 Android TCP / UDP 工作协程数和节点至目标的连接数。
- H2 阶段在节点侧阻断测试端口的 UDP。H2 回显成功后 App 退到后台，留 35 秒给建连及近期业务窗口，然后在节点网卡记录目标地址和端口上所有客户端 TCP/UDP 报文的计数与时间。独立控制端口不在窗口内，抓包期间没有轮询连接。结束后用新的 TCP 回显确认可用性。

## 账户续期

`nexus-node ledger DB renew USER UNTIL` 接受未来的 RFC 3339 时间或 `never`。续期与审计在同一事务提交，同一账号下的所有设备共用新到期时间。已撤销设备保持撤销。管理页复用“账号有效天数”输入，有限期账号从当前到期日与服务器当前时间的较晚者开始顺延。设备从下一次认证回执刷新日期。

独立节点在 H2、H3 上验过续期后用原设备重新连接，CLI 测试覆盖过去时间、未知用户、永久有效和审计。NexusLab 定向运行 `go test -race -count=1 -run 'TestAdminListings|TestAuthenticatedHealthAndRenewal' ./cmd/nexus-node ./integration`。H2 的两项保护和恢复测试也已通过。抓包门槛另有边界检查，599 秒、3 个客户端包或有应用请求均会报错并保留观察记录。

## Release 体积和校验

Debug/实验室包仍能经 SSH 上传内置程序，Release 的 SSH 会话让目标机从本项目 GitHub Release 的同版本标签取对应架构文件。客户端取 APK 内的 SHA-256，与远端临时文件的实际 SHA-256 比较，通过后才允许执行。两种架构都覆盖 V1 和 V2，V1 部署与兼容代码保留。版本发布准备脚本检查 arm64 与 universal APK 的摘要，逐一配对待发布的四个文件；误装程序入 APK、替换发布资产都会失败。

两个体积样本均为启用 R8 和资源裁剪的 arm64 Release，使用相同的 JDK、Gradle、可复现时间戳与本地测试签名。基线 APK 内 Linux V2 两个架构的 ZIP 压缩条目合计 39,861,359 B，V1 合计 5,558,249 B。实际比较采用整个 APK 文件的字节数。正式发布需用新标签同时发布 APK 与配套节点文件。历史 v1.0.1 标签属于旧版本。本轮所有资产留在本地，未验证尚未发布的新标签的公网下载。

| arm64 Release | APK 字节数 |
|---|---:|
| 基线 | 72,488,615 |
| 含最终续期 UI 和 H2 改动 | 27,071,707 |
| 减少 | 45,416,908（62.65%） |

基线和最终 arm64 APK 通过 apksigner 校验。最终 15 秒 H2 回收版重新离线合编了普通 AAR，arm64 APK 的 SHA-256 为 `a115fc8ec29d187da3bcfb1bac0c6b7876158fc95297647850b3ece1ff7ed503`。实际 arm64 和 universal Release 通过 `tools/prepare_android_release.py TAG APK_DIR NODES OUT` 的配对检查。Windows 构建环境、Go 可执行目录和 GOMODCACHE 已写入 `docs/ANDROID.md`。测量前曾因复用 AAR 的 Gradle provider 未就绪而改用离线源码重建。新任务的首次配置遇到 Android variant 延迟注册，修正后构建通过。

## H2 空闲和按需重连

首次使用“关闭本端 TCP keepalive，最后一条 H2 流结束 30 秒后回收连接”的候选。相同的 35 秒初始化窗口后，600.095 秒内记录 3 个客户端 TCP 报文（1 个有负载，2 个控制报文），时间分别为 0.474、0.475、0.475 秒；没有 HTTP 请求。本轮超过 2 包门槛，保留为失败。锁定版 HTTP/2 库从最后一条流释放时开始计时。到时仅在没有活动流和预留流时关闭 TLS 套接字。三个集中报文符合一次连接关闭的特征，单向包头计数不能识别加密正文。最终 Android 版将无流连接回收时间缩短至 15 秒，保留正常 TLS 关闭和新业务按需重拨。复测沿用同一抓包阶段、方向、窗口和全部客户端报文的上限。

15 秒回收版在 600.056 秒的节点窗口内收到 0 个客户端报文和 0 条应用请求。客体观察时长 600,006 ms，意外承载状态和 UID 唤醒闹钟均为 0。窗口结束后，新 H2 TCP 回声通过。辅助包头观察以第一个客户端 SYN 为零点，21.94 秒见到客户端 FIN，637.12 秒再次见到客户端 SYN。采样未持久化报文正文。长稳阶段使用同一 UDP/TCP 桥接实现，在健康 H3 上完成；仅 H2 的无流回收时间在最后这轮调整。

`expiry` 已恢复客体自动校时。已卸载本轮两个实验包，关闭雷电实例 0。本次 NexusLab 服务正常退出，临时回声地址已移除，原有 V1 的 nexus-node 与 nexus-claim 仍为 active。

### 需要修改

1. **H3 会断开空闲的长连接。**这个问题在之前的版本就有，不是本轮引入的。
   - 原因：QUIC 的空闲超时是 30 秒，客户端和 Caddy 都没有发保活包。
   - 复现：新增临时测试 `TestZZIdleOpenFlow`。打开一条 TCP 流，回声一次，静默 45 秒后再写入。
     - H2 通过：服务器的 TCP keepalive 每 15 秒一次，连接得以保持。
     - H3 失败，报错 `after-45s write: io: read/write on closed pipe`。
   - 影响：微信、Telegram、FCM 推送这类常驻长连接，在 H3 上每 30 秒就被断一次。这正是常开 VPN 用户最常见的场景，会出现收不到推送、频繁重连、反而更耗电的情况。
   - 修改方向：H3 上有活动的业务流或 UDP 会话时，每 15 秒发一次 QUIC PING（与 Chrome 在有活动流时的做法一致）。
     - 传输参数里的 `idle_timeout=30000` 保持不变，以免改变指纹。
     - 没有业务流时维持现状：不发包，30 秒后自然关闭。
2. **Release 部署依赖服务器上有 curl。**部分精简版 Debian 镜像没有 curl。没有 curl 时改用 wget，其余校验步骤不变。M4 在 Debian VPS 上实测。

### 说明

- 长稳测试在 H3 上完成，H2 只在最后一轮把释放时间调成了 15 秒，这个改动不影响长稳结论。
- Release 下载地址取 `v${VERSION_NAME}`，因此发布标签必须与 versionName 一致。现有发布流程已满足这一点。

### 结论

M3-3 的四项要求全部达标。上面第 1 项是上线前必须修的问题，第 2 项是一处小改动。两项合并成一个小轮次（M3-4），之后进入 M4 公网测试。
