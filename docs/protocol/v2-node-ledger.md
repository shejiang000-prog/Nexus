# V2 节点账本 · M1 管理与故障处理

在 Caddy 的 nexus handler 设置绝对路径 `ledger_path`。节点服务账户独占数据库目录，Linux 目录权限设为 0700，数据库权限为 0600。首次创建在事务内建表并写入 schema 版本 2。旧版第一次打开时，在同一写事务中迁移审计表并保留已有序号和归属。旧的内存设备表继续支持静态配置；同一 handler 同时指定账本与静态设备会启动失败。

|表|键与用途|
|---|---|
|users|16 字节用户 ID。可空的到期秒数与字节额度。当前只支持不限额用户；已填额度的账户暂不准入。|
|invites|32 字节令牌的 SHA-256 摘要为主键，记录用户、到期时间和剩余名额 0/1。原令牌只在生成时返回。|
|devices|16 字节随机设备 ID，压缩 P-256 公钥和兑换 ID 各自唯一；邀请外键确定归属用户。保存可选显示名和撤销时间。已领取设备的使用期限独立于原邀请。|
|audit|单调序号、时间、create_user/invite/redeem/revoke 类型、相关用户或设备 ID。与业务写入同事务提交。审计中不保存令牌、签名及 exporter。|

## 邀请兑换

HTTP/2 和 HTTP/3 共用同源 HTTPS POST。客户端在已完成的 TLS 1.3 连接上取 exporter，为规范第 2 节的兑换字节签名。请求最多 4096 字节，拒绝重复字段、未知字段、错误长度、非法编码和无效曲线点。失败转给后续站点处理，保留在此路径的凭据不会进入回落正文。成功返回版本 2 和设备 ID，禁止缓存。

按连接对端 IP 限制兑换请求，每秒最多 16 次，同一窗口最多跟踪 4096 个地址。IPv4 映射地址与对应 IPv4 共用计数；超限走失败回落。只读查询核对摘要、期限、用户资格及剩余名额，已领取者只允许原身份幂等重试。通过后才开始 `BEGIN IMMEDIATE`，在写事务内再次核对。先检查邀请和用户期限，再按 request_id 查询已兑换结果。相同邀请、公钥和 ID 在重新证明当前连接后可取回原设备 ID。首次兑换在同一事务中扣名额、创建设备和写审计，任一步出错全部回滚。已撤销设备无法用旧邀请恢复。

## 撤销

节点每 150 ms 用独立读连接检查 SQLite `data_version`。写入提交后刷新设备快照，查询成功且全部公钥有效才替换旧快照。鉴权和登记活动流都在内存里检查设备资格与账户期限。数据库查询期间不持有活动流互斥锁。注册与快照替换在同一把锁下执行。撤销或到期后关闭相关连接的 TCP 和 UDP 业务。到期时间按 Unix 秒计，新流在到期时立即拒绝，活动流由监视器清理。

账本使用 WAL。其他进程持写锁时，撤销必须等事务提交才生效；读者可以继续读取最近提交的状态。单次读取失败既不能证明设备已撤销，也不能证明没有新撤销。监视器保留旧快照，以 300 ms 间隔重试，首次错误写错误日志，恢复后记录恢复日志。已知账户到期仍在重试期间执行。

连续失败满 **30 秒** 后清空授权缓存、拒绝新业务并关闭所有活动流。该值是 3 秒短锁用例的十倍，为短时维护留出余量，也限定了读故障时继续信任旧状态的时间。文件删除、替换或权限偏离 0600 同样视为失败。修复原文件及权限后，成功读取完整快照才能恢复；替换数据库文件后需要重新打开节点。故障期间不能保证已提交的跨进程撤销在 1 秒内可见。备份时须使用支持 SQLite WAL 的一致性备份方式。

## 本地管理命令

用节点服务账户执行，DB 参数为绝对路径。命令可与运行中的节点共用同一账本目录。用户和设备参数使用 32 个十六进制字符；时间使用带时区的 RFC 3339。下列命令中的大写词为占位符。

```text
nexus-node ledger DB create-user [EXPIRES_AT]
nexus-node ledger DB invite USER_ID EXPIRES_AT
nexus-node ledger DB users
nexus-node ledger DB devices
nexus-node ledger DB revoke DEVICE_ID
nexus-node ledger DB audit
```

创建用户输出新 ID。生成邀请的标准输出只含一次性令牌，按凭据交付，避免重定向至公共日志。数据库仅保存其摘要。用户、设备与审计列表均逐行输出 JSON。创建用户、发邀请、兑换、撤销的状态变更与对应审计行在同一事务内提交。对已撤销设备重复撤销不重复记账。管理命令不返回原邀请、私钥、签名或 exporter。

## 后续额度账本设计

下一次 schema 迁移拟新增 `quota_leases(lease_id, user_id, device_id, reserved_bytes, committed_bytes, state)`。租约 ID 唯一，写数据前在同一写事务校验用户剩余额度并预留；结算按用户可见的有效载荷释放余额，以租约 ID 保证重复结算幂等。未结算预留在节点重启后冻结，留给对账流程处理。正式启用限额需要并发超卖、部分写、进程中断及重复结算测试。备份恢复演练和额度执行仍待实现。
