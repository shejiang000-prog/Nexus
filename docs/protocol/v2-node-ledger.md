# V2 节点账本 · M1 管理与故障处理

在 Caddy 的 nexus handler 设置绝对路径 `ledger_path`。节点服务账户独占本地数据库目录，Linux 目录权限设为 0700，数据库权限为 0600。V2 用于私人节点分享。新建账本使用 schema v4，仅保存授权和审计，不计量用户流量。旧实验库无法直接打开，请保留原件并指定新路径重建用户、签发新邀请。使用支持 SQLite WAL、文件锁及硬链接的本地文件系统。静态设备配置仍可单独使用；同一 handler 同时指定账本与静态设备会启动失败。

|表|键与用途|
|---|---|
|users|16 字节用户 ID 和可空的到期秒数。|
|invites|32 字节令牌的 SHA-256 摘要为主键，记录用户、到期时间和剩余名额 0/1。原令牌只在生成时返回。|
|devices|16 字节随机设备 ID，压缩 P-256 公钥和兑换 ID 各自唯一；邀请外键确定归属用户。保存可选显示名和撤销时间。已领取设备的使用期限独立于原邀请。|
|audit|单调序号、时间、操作、相关用户或设备 ID。用户创建、发邀请、兑换和撤销与审计在同一事务提交。|

## 邀请兑换

HTTP/2 和 HTTP/3 共用同源 HTTPS POST。客户端在已完成的 TLS 1.3 连接上取 exporter，为规范第 2 节的兑换字节签名。请求最多 4096 字节，拒绝重复字段、未知字段、错误长度、非法编码和无效曲线点。失败转给后续站点处理，保留在此路径的凭据不会进入回落正文。成功返回版本 2 和设备 ID，禁止缓存。

按连接对端统计兑换。每个一秒固定窗口内，每个 IPv4 地址或 IPv6 /64 最多放行 16 次，IPv4 映射地址与对应 IPv4 共用计数。全节点所有 handler 合计最多放行 256 次，即允许 16 个独立来源同时用满各自预算，同时限制轮换来源所能触发的正文解析、验签和账本查询量。超过任一上限均交给回落站点。只读查询核对摘要、期限、用户资格及剩余名额，已领取者只允许原身份幂等重试。通过后才开始 `BEGIN IMMEDIATE`，在写事务内再次核对。先检查邀请和用户期限，再按 request_id 查询已兑换结果。相同邀请、公钥和 ID 在重新证明当前连接后可取回原设备 ID。首次兑换在同一事务中扣名额、创建设备和写审计，任一步出错全部回滚。已撤销设备无法用旧邀请恢复。

## 撤销

节点每 150 ms 用独立读连接检查 SQLite `data_version`。写入提交后刷新设备快照，查询成功且全部公钥有效才替换旧快照。鉴权和登记活动流都在内存里检查设备资格与账户期限。数据库查询期间不持有活动流互斥锁。注册与快照替换在同一把锁下执行。撤销或到期后关闭相关连接的 TCP 和 UDP 业务。到期时间按 Unix 秒计，新流在到期时立即拒绝，活动流由监视器清理。

账本使用 WAL。其他进程持写锁时，撤销必须等事务提交才生效；读者可以继续读取最近提交的状态。单次读取失败既不能证明设备已撤销，也不能证明没有新撤销。监视器保留旧快照，以 300 ms 间隔重试，首次错误写错误日志，恢复后记录恢复日志。已知账户到期仍在重试期间执行。

连续失败满 **30 秒** 后清空授权缓存、拒绝新业务并关闭所有活动流。该值是 3 秒短锁用例的十倍，为短时维护留出余量，也限定了读故障时继续信任旧状态的时间。文件删除、替换或权限偏离 0600 同样视为失败。修复原文件及权限后，成功读取完整快照才能恢复；替换数据库文件后需要重新打开节点。故障期间不能保证已提交的跨进程撤销在 1 秒内可见。备份时须使用支持 SQLite WAL 的一致性备份方式。

## 配置重载

同一进程重载指向同一真实路径的配置时（包括符号链接别名），新旧 handler 共享账本和撤销监视器。已建立的 H2/H3 业务继续，新设备可以加入。配置失败时保留原配置。当 `ledger_path` 改为另一个数据库，且旧库的最后一个 handler 释放引用，旧库的活动 TCP/UDP 流关闭；后续连接按新库认证。更改路径会切换授权域。恢复备份到原路径属于替换数据库文件，需要停机并关闭所有数据库句柄。

## 本地管理命令

用节点服务账户执行，DB 参数为绝对路径。命令可与运行中的节点共用同一账本目录。用户和设备参数使用 32 个十六进制字符；时间使用带时区的 RFC 3339。下列命令中的大写词为占位符。

```text
nexus-node ledger DB create-user [EXPIRES_AT]
nexus-node ledger DB invite USER_ID EXPIRES_AT
nexus-node ledger DB users
nexus-node ledger DB devices
nexus-node ledger DB revoke DEVICE_ID
nexus-node ledger DB revoke-user USER_ID
nexus-node ledger DB backup ABSOLUTE_PATH
nexus-node ledger DB audit
```

创建用户输出新 ID。生成邀请的标准输出只含一次性令牌，按凭据交付，避免重定向至公共日志。数据库仅保存其摘要。用户、设备与审计列表均逐行输出 JSON。创建用户、发邀请、兑换、撤销的状态变更与对应审计行在同一事务内提交。对已撤销设备重复撤销不重复记账。管理命令不返回原邀请、私钥、签名或 exporter。

创建用户与邀请都要求指定的到期秒数晚于当前时间。撤销未知设备时 CLI 报错并返回非零，已撤销设备提示后返回 0。`revoke-user` 撤销命令提交时该用户已有的全部设备；现有邀请和用户记录继续保留。

## 在线备份与离线恢复

1. 用服务账号运行 `nexus-node ledger /absolute/ledger.db backup /absolute/backup.db`，备份目录须受控，目标须不存在。命令在目标目录的私有文件执行 `VACUUM INTO`，以只读连接执行 `PRAGMA integrity_check`，通过后原子发布 0600 副本。记录成功的时间与备份所在目录。
2. 恢复时先停止节点和所有访问该库的 CLI。将当前主库和同名 `-wal`、`-shm`、`-journal`（如存在）一并移至单独的受控目录留存。以服务账户把备份复制为原账本路径，设置 0600。保留备份原件，原实例保持停止直至替换完成。
3. 启动节点，核对 `users`、`devices`、`audit`。以快照为恢复点，较晚的撤销、邀请兑换及其他审计不会包含在较早的副本中。快照内已使用的邀请不能再兑换新设备。核对备份点的审计序号，验证原设备的准入和撤销状态。
