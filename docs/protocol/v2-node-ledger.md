# V2 节点账本 · M1 首批实现

在 Caddy 的 nexus handler 设置绝对路径 `ledger_path`。节点服务账户独占数据库目录，Linux 目录权限设为 0700，数据库权限为 0600。首次创建在事务内建表并写入 schema 版本 1。旧的内存设备表继续支持静态配置；同一 handler 同时指定账本与静态设备会启动失败。

|表|键与用途|
|---|---|
|users|16 字节用户 ID。可空的到期秒数与字节额度。当前只支持不限额用户；已填额度的账户暂不准入。|
|invites|32 字节令牌的 SHA-256 摘要为主键，记录用户、到期时间和剩余名额 0/1。原令牌只在生成时返回。|
|devices|16 字节随机设备 ID，压缩 P-256 公钥和兑换 ID 各自唯一；邀请外键确定归属用户。保存可选显示名和撤销时间。已领取设备的使用期限独立于原邀请。|
|audit|单调序号、时间、redeem/revoke 类型、设备 ID。与业务写入同事务提交。撤销查询使用部分索引，审计中不保存令牌、签名及 exporter。|

## 邀请兑换

HTTP/2 和 HTTP/3 共用同源 HTTPS POST。客户端在已完成的 TLS 1.3 连接上取 exporter，为规范第 2 节的兑换字节签名。请求最多 4096 字节，拒绝重复字段、未知字段、错误长度、非法编码和无效曲线点。失败转给后续站点处理，保留在此路径的凭据不会进入回落正文。成功返回版本 2 和设备 ID，禁止缓存。

`BEGIN IMMEDIATE` 在读取名额前取得写事务。先检查邀请和用户期限，再按 request_id 查询已兑换结果。相同邀请、公钥和 ID 在重新证明当前连接后可取回原设备 ID。首次兑换在同一事务中扣名额、创建设备和写审计，任一步出错全部回滚。已撤销设备无法用旧邀请恢复。

## 撤销

管理代码调用 `Ledger.Revoke`。本句柄在提交后触发活动业务的关闭回调；持有同一文件的其他节点句柄有活动业务时每 150 ms 读取已提交的撤销审计。H2 关闭对应 TCP 连接，H3 关闭绑定的 QUIC 连接，同时终止其 TCP 流和 UDP 关联。注册流时再次检查数据库，避免在设备鉴权与登记之间漏掉撤销。新请求也复查设备。撤销操作须使用账本接口，直接编辑表会绕过审计。当前用例覆盖活动连接，空闲无流连接只在下一次请求时检查设备。

## 后续额度账本设计

下一次 schema 迁移拟新增 `quota_leases(lease_id, user_id, device_id, reserved_bytes, committed_bytes, state)`。租约 ID 唯一，写数据前在同一写事务校验用户剩余额度并预留；结算按用户可见的有效载荷释放余额，以租约 ID 保证重复结算幂等。未结算预留在节点重启后冻结，留给对账流程处理。正式启用限额需要并发超卖、部分写、进程中断及重复结算测试。目前还缺运维 CLI、备份迁移、用户主动到期断流、额度执行和多用户负载验收。
