# Nexus 发布前安全审查

审查基线为 `release/prep-1@90fb8eb`。范围包括本地 Android 客户端、Rust 输入边界、服务器安装和邀请脚本、GitHub 发布工作流。下表区分源码检查、已执行的回归和仍需设备或网络条件的验证。没有确认高危问题。

## 发现与处置

| 严重度 | 位置 | 触发条件与影响 | 处理和验证 |
|---|---|---|---|
| 中 | `CompatEngine.resolved`、`ShoesEngine.resolvedClient` | 导入的节点直接指定本机地址，或域名解析到本机时，连接及真连测试可能访问手机自身的服务。 | 两引擎共用 `NodeAddress.kt`，用物理网络解析一次并固定数字地址，TLS 身份仍使用原主机。拒绝回环、未指定、链路本地、组播、240.0.0.0/4 及手机自身接口地址。**评审修订：** 局域网、CGNAT、ULA 与 198.18.0.0/15 保留可用——家用服务器和路由器侧代理（如 OpenClash fake-ip 应答）合法使用这些地址；订阅方本就能看到全部流量，指向局域网的残余风险记为低并接受。实验室节点因此无需测试专用放行钩子。 |
| 中 | `CompatEngine.convert`、`NodeFormats` | 分享链接把连接参数交给原生转换器。仅提取单个出站不足以约束其内部设置，错误信息还可能带回提供方文本。 | 校验协议、传输、出站顶层字段、重复参数和最终对象中的控制字符、文件及路由相关字段；拒绝关闭证书验证。额外参数只有在去掉后转换结果完全相同时才接受，保留机场常见的展示元数据。错误使用固定文案。首轮过严筛掉真实来源的节点，修订后通过格式和真机 Xray 检查。 |
| 中 | `Subscriptions.parse`、`checkedObject`、VMess 与邀请 JSON 入口 | 有体积上限的输入也能包含过深结构、歧义的重复键或 YAML 别名，导致解析负担或同一内容的解释不一致。 | JSON 在建树前检查重复键及 24 层深度；YAML 预读事件、拒绝别名、限制深度和事件数。保留 512 KiB、每来源 2,048 个节点、单链接 16,384 字符上限。security 测试覆盖重复键、双层 Base64、超长和超量输入，以及带 JSON 标点的普通显示名。 |
| 中 | `Subscriptions.fetch` | 只有单次连接和读取超时，跨跳转的缓慢响应可长时间占住刷新。 | 请求共用 30 秒预算，到期调用 disconnect；每跳保留连接 10 秒、读取 15 秒限制。最多三次跳转，初始地址和每跳均须 HTTPS 且无用户信息。响应头仅取前 256 字符内的额度数字字段。security 使用内存 HTTPS 连接验证超时实际中断等待、到期结果被丢弃，以及拒绝跨协议跳转；refresh 检查失败保留原记录。公网慢速 HTTPS 全程计时未单独测量。 |
| 中 | `tools/node_admin.py:258`、`Server.process_request_thread` | TLS/HTTP 读取持续有进展时，原有单次超时无法限制整次请求。八个接收槽可能一直被占，其他设备无法领取。 | 经授权给每个获准处理的连接加 15 秒总时限，覆盖握手及 HTTP 收发，正常退出取消并回收计时器。WSL 用 socketpair 验证到期和提前结束，另跑完整注册表检查。数据库、签名操作有各自执行边界，计时器控制网络等待。 |
| 中 | `QuickAccess.kt` 的 `ConnectTile.onClick` | 系统允许锁屏访问快捷面板时，其他人可能切换手机已有 VPN。 | 使用系统解锁回调后才切换，已解锁时直接操作。security 测试验证回调前状态不变，解锁路径及正常路径各只执行一次。厂商锁屏界面的手动点击未测。 |
| 低 | `NexusApp`、WorkManager 初始化 | 真机 logcat 的 WorkManager 网络状态消息命中地址样式，后台任务编号也会进入日志。 | 在 Android 创建其他组件前为固定版本 WorkManager 2.10.1 设置 ERROR 日志门槛。该版会沿用第一个 logger，单独设置 Configuration 在真机上仍观察到 DEBUG。前后真机统计见交接。 |
| 低 | `OwnerAccess.prepare` | 生成管理密钥时，中间输出流保留额外明文字节直到垃圾回收。 | 在 finally 中擦除自有缓冲区、销毁临时密钥对象；持久化使用 Android Keystore 的 AES-GCM 包装。JSch/JVM 内部的临时副本不在应用清零保证内。 |
| 低 | `Invitation.parse`、`SimpleServer.kt`、`PRIVACY.md` | 邀请展示名可含方向控制字符，旧系统版本复制邀请未标记敏感，原隐私文案缺少前台剪贴板识别。 | 限定邀请名长度并拒绝控制、格式字符，复制邀请标记为敏感，补充前台识别和确认边界。第三方输入法及剪贴板实现可能有不同表现。 |
| 低 | `.github/workflows/release.yml` 的 build/publish | 原先 APK 和对照用的校验文件一起传输，发布说明也没有独立对照值。 | 构建 job 另传清单及发布说明的合成摘要。发布 job 先与该值比较，再严格验证 APK 清单。用本地样本分别验证正常、说明变化、APK 变化；未触发 GitHub 发布。 |
| 低 | `crates/nexus-android/src/{split,forwarding}.rs` | 过多解析器参数可能先整表分配再拒绝，超长 TCP DNS 长度窄化可能产生错误帧。 | 先限量读取解析器，再检查数量；两处发送共同使用检查过的 u16 长度。Windows、Linux 固定种子边界测试通过。 |
| 低 | `split.rs` 的 DNS 学习表 | 国内、国外域名共享同一应答 IP 时，后来的裸 IP 连接可在学习有效期内沿用直连分类。 | 保留现行分流语义和 TTL；只凭裸 IP 无法可靠区分同一地址上的两个域名。 |

## 其他审查覆盖

- **订阅及引擎。** 节点名作为显示数据。结构化节点经 `NodeFormats` 生成分享链接，单一转换出站才进入应用配置；应用生成入站、路由和受保护套接字。shoes 从已知字段重新构造 JSON、校验主机、端口、协议、SNI、ALPN 和可选证书固定值。订阅无法交付一份可直接运行的完整引擎配置或指定 Unix socket。检查了刷新失败、崩溃记录及界面文案的错误路径。下载和 DNS 时限仍依赖系统网络栈。
- **邀请与领取。** `NodeManager.kt:192` 限定链接前缀、长度、Base64、版本、HTTPS 路径、固定证书摘要和令牌格式。领取校验叶证书有效期及摘要、禁重定向、绑定设备签名。其他 App 可以提供符合格式的邀请，来源身份由用户确认；扫描、深链与剪贴板不自行领取。服务端 `node_admin.py` 限制设备名为 64 字符内可打印文本，参数化 SQL 和事务控制名额，同一身份重复领取幂等，撤销在注册表流程中验证。所有者列表用原生文本显示名称。
- **SSH 管理与部署。** `NodeManager.session/install/owner` 的管理动作来自固定集合，DNS、名称、设备 id、端口和限额由 JSON 标准输入传递；写入 authorized_keys 的内容来自校验后的本机公钥。SSH 首次确认后固定主机密钥，后续不匹配停止操作；重新绑定需要用户显式忘记旧绑定并重新确认。`restrict` 限制转发、终端等 SSH 能力，持有该部署管理密钥仍具备远程管理权限。安装脚本检查支持的系统、架构、固定安装名称、目录所有权和链接，升级核对摘要；身份目录有私有权限，运行服务的是 nexus-node。对未改动的 `install_node.py` 在 WSL 临时目录验证了五种配置错误和已有安装均在写入前被拒。未在 Android 上重走安装、权限落盘和迁移。
- **Rust。** 读 OPEN、长度帧以及 DNS 应答、解析器指令和转发长度分别有固定种子 100,000 轮输入，包含合法前缀、截断和变异。检查返回值、长度及输出条数；没有做堆分配剖析或证明所有输入空间。线上格式沿用基线。
- **Android 组件。** 主 Manifest 的 MainActivity 对外接收深链；ConnectTile 需要系统的 BIND_QUICK_SETTINGS_TILE；BootReceiver 与 TunnelService 均非导出，VPN 服务有 BIND_VPN_SERVICE。应用代码创建的 PendingIntent 使用 IMMUTABLE。应用关闭明文 HTTP 和系统备份，数据提取规则覆盖设备迁移。该应用层明文策略不替代原生引擎各协议自己的传输设置。
- **发布。** 发布工作流的第三方 action 均固定到提交 SHA。签名凭据仅在签名步骤注入，临时目录设置私有权限并退出清理，只有发布 job 有 contents: write。构建步骤包含项目代码，可信 tag 与签名密钥管理仍是发布前提。没有使用实际发布密钥或执行线上验证。
- **隐私。** 按程序入口核对了 GitHub 检查更新和反馈页、Cloudflare 测速与连通探针、example.com 备用验证和 ipinfo.io 出口查询，以及用户选择的订阅、DNS 和节点。浏览器和节点也会产生自身网络活动。真机日志结果见本轮交接。用户要求保留当前网络；没有完整网络抓包，因此没有实测证明所有出站域名与声明逐一相符。

托管安全扫描的本机工作目录未通过权限预检，未生成托管扫描报告。本表依据源码、设备 instrumentation 和本地测试。
